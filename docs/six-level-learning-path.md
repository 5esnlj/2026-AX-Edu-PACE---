# 6수준 진단과 나의 배움길 (L3)

학생의 **한국어 자가 점검 → 교사 채점 → 나의 배움길**을 하나의 흐름으로 연결했습니다. `L3 개별 학습 경로 학생용.zip`의 사실과 제안을 구분하는 방식을 적용하고, `[해커톤 개발] 설계안 - 학습자 수준 진다.pdf`의 36문항과 판정 규칙을 사용합니다.

## 기존 데이터 변경

사용자 요청에 따라 기존 **4단계 수준은 보존·환산하지 않습니다.** 첫 실행 때 이전 학생 수준·생활 한국어 값·출처를 초기화하고, 4단계 기반 L1 프로필을 삭제합니다. 별도 백업 테이블은 만들지 않습니다. 학생은 모두 **진단 전**으로 시작하며, 새 6수준 진단 응답과 채점 결과만 수준·리포트·배움길에 반영됩니다.

새 진단 결과는 SQLite에 저장되어 재실행해도 유지됩니다. 시작할 때마다 새 결과를 초기화하지 않습니다. 기존 수업 자료의 본문·메모·교과 이해 확인 응답은 유지하며, 기존 배포 자료의 과거 수준 숫자는 화면에 표시하지 않습니다. 과거 고정 배움길의 활동 완료 수를 새 배움길에 합산하지 않습니다.

## Windows / VS Code에서 적용

VS Code에서 이 프로젝트 폴더를 열고, 실행 중인 터미널에서 `Ctrl+C`로 서버를 종료합니다. 변경 사항이 있는 파일은 VS Code의 소스 제어에서 먼저 확인하고 보관하세요. 로컬 파일을 강제로 덮어쓰는 명령은 필요하지 않습니다.

```powershell
git fetch origin
git switch feature/six-level-learning-path
git pull --ff-only
npm.cmd install
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
npm.cmd run dev
```

처음 받은 폴더여서 `.venv`가 없으면 Python 설치 후 `py -m venv .venv`를 먼저 실행합니다. 브라우저에서 터미널에 나온 `http://localhost:5173` 주소를 엽니다.

## 체험 순서

1. **학생**으로 입장해 **한국어 자가 점검 → 6수준 진단 시작하기**를 누릅니다.
2. 듣기 12문항, 읽기 12문항에 차례대로 응답합니다. 모르면 **아직 모르겠어요 (무응답)**를 선택합니다. **임시저장** 후 다시 열어 이어 할 수 있습니다.
3. 쓰기 과제를 하나 제출하면 교사 채점을 기다립니다. 같은 학생으로 다시 입장하거나 **채점 결과 새로고침**으로 이어갑니다.
4. **교사 → 학생 관리 → 해당 학생의 진단 보기·채점**을 엽니다. R1~R4 각각 0~3점을 선택하고 **채점 저장 및 다음 과제 안내**를 누릅니다. 과제 기준과 학생 응답이 함께 보입니다.
5. 쓰기 후 말하기를 진행합니다. 학생은 최대 3분 녹음, 12MB 이하 음성 파일 업로드, 또는 대면 말하기를 선택합니다. 대면 말하기는 교사의 관찰 기록이 필수입니다. 녹음은 해당 학생과 교사만 조회합니다.
6. 완료 후 **나의 배움길**에 활동·확인 기준·추천 근거가 나타납니다. 해 본 활동과 필요한 도움을 기록하면 저장되며, 교사도 같은 기록을 확인합니다.
7. 전체 채점 전에는 확인된 영역만 사용한 **임시 배움길**입니다. 결과가 바뀌면 최신 진단에 맞는 경로로 갱신합니다. 이전 결과의 경로에 새 기록을 쓰는 요청은 거절합니다.

같은 브라우저에서는 로그아웃 버튼으로 교사·학생 역할을 바꿉니다. 동시에 체험하려면 일반 창과 시크릿 창에 서로 다른 역할로 입장하세요. 교사는 음성 인식 결과 대신 녹음 또는 직접 관찰한 수행을 평가합니다.

## 6수준과 판정

| 수준 | 이름 |
| ---- | ---- |
| 1    | 시작 |
| 2    | 초기 |
| 3    | 발달 |
| 4    | 확장 |
| 5    | 연결 |
| 6    | 도달 |

- 듣기·읽기: 각 수준에 2문항. 2개 정답 P, 1개 B, 0개 F. 전체 24문항을 실시합니다.
- 쓰기·말하기: 수준 1부터 실시합니다. R1 ≥ 2이고 합계 ≥ 8이면 P. 수준 5·6은 R3·R4도 각각 2 이상이어야 합니다. R1 ≥ 2이며 합계 7, 또는 합계 ≥ 8이나 상위 수준 R3·R4 조건 미달이면 B, 나머지는 F입니다.
- B/F가 두 수준 연속이면 수행 영역을 중단합니다. 이후 과제는 **미실시**로 표시하고 층위 계산에 0점을 반영합니다. 두 번의 B도 중단 조건입니다.
- B 바로 다음이 P이면 영역당 한 번만 B를 P로 보정합니다. 여러 후보가 있으면 낮은 수준의 첫 후보를 적용합니다. F는 보정하지 않습니다.
- 영역 수준은 1부터 연속 P인 마지막 수준입니다. 다음이 B이면 `+`를 표시합니다. 떨어진 상위 수준의 P는 비연속 통과로 교사에게 표시합니다.
- 종합은 네 영역 정수 수준 중앙값을 내림하고, 최저 영역 + 2를 상한으로 적용합니다. 채점 전에는 종합을 확정하지 않습니다. K=0인 영역은 1수준으로 올리지 않고 **선생님과 다시 확인해요**로 표시합니다.
- 층위 B/T1/T2/T3/C 숙달도, 첫 병목, 생활–교과 한국어 격차, 교과별 선별 결과, 추측 의심·이해>표현·교과 편차를 계산합니다. 교과 개념의 오류는 언어 점수에서 감점하지 않고 별도 기록합니다.
- 학생 결과에는 쉬운 이름·6칸 계단·세 가지 층위 상태를 사용합니다. C 합산·원점수·해석 플래그는 교사 화면에 둡니다. 교과별 결과에는 **짧게 확인한 결과**를 붙입니다. 시작·초기 학생은 한 번에 한 활동 목표를 보고, 나머지 상세 결과는 펼쳐 볼 수 있습니다.

설계안의 학생 A 예시는 자동 테스트로 대조합니다. 결과는 **듣 5+ / 읽 5 / 쓰 5 / 말 4+ / 종합 5 / 병목 C / 격차 0.46 / 사회 ≤3 재확인**입니다. 이 예시를 실제 데모 학생에게 자동 배정하지 않습니다. 첨부 코드의 [학생 A 참고 데이터](reference/l3-student-a.json)는 문서로만 보관하며 실행 코드에서는 읽지 않습니다.

## 첨부 코드에서 바뀐 점

- 학생 A 고정 JSON·고정 C 병목 대신 로그인한 학생의 서버 진단 결과를 전달합니다.
- 별도 FastAPI 서버와 화면을 띄우는 대신 기존 API·메뉴·세션·SQLite에 통합합니다.
- 첨부 코드의 OpenAI 호출은 기존 **Solar 어댑터**를 사용하도록 연결합니다. 별도 OpenAI 키는 필요하지 않습니다.
- LLM은 활동 제안만 생성합니다. 수준·병목·교과 프로파일은 판정 코드가 계산하며, LLM이 덮어쓸 수 없습니다. 각 활동의 근거 ID는 실제 진단 근거 목록에 있는지 검증합니다.
- 이름·국적·학생 ID·실제 응답·녹음·교사 관찰 원문을 L3 모델에 전달하지 않습니다. 구조화된 진단 결과만 전달합니다.
- 페이지를 열 때는 유료 호출이 없습니다. 규칙 기반 활동을 보여 주고, `IEUM_AGENT_PROVIDER=solar`일 때 **Solar로 배움길 만들기**를 누르면 요청합니다. 실패하면 기존 경로를 유지합니다.
- 활동 완료는 학생이 남기는 학습 기록입니다. 수준을 자동으로 올리거나 정답 검사로 취급하지 않습니다.
- L1 자료 재구성은 새 진단의 영역·종합·교과·병목 정보를 기본으로 사용합니다. 교사가 별도로 연결한 6수준 시연 프로필은 출처를 구분하며, 학생이 새 진단 응답을 제출하면 해제됩니다.

## 설계안에서 확인이 필요한 부분

1. **그림 원본이 없습니다.** PDF의 `[그림]` 자리는 그림 기호와 표로 구현했습니다. 쓰기 2·말하기 2의 구체적인 수요일 시간표도 없어, 추가한 예시 표라는 안내와 함께 제공합니다. 정식 평가용 시각 자료는 교사 검수가 필요합니다.
2. **말하기 1·2의 과제 문구와 R1·R2 기준이 불일치합니다.** 문항과 채점 기준을 임의 수정하지 않고 교사 화면에 경고와 관찰 메모를 제공합니다. 실제 적용 전 팀에서 질문과 필수 요소를 맞춰야 합니다. 이 항목은 자동 채점하지 않습니다.
3. **층위 숙달도의 M1~M6 변환 구간이 정의되지 않았습니다.** 예시의 M6·M4만 보고 구간을 만들지 않습니다. 명시된 원점수·비율과 안정/형성 중/미형성 기준만 사용합니다. 영역별 한국어 1~6수준과는 별도입니다.
4. K=0의 일반 종합 처리 규칙은 미정이므로, PDF의 학생 표시 지침에 따라 전체를 재확인으로 표시합니다.
5. TTS는 브라우저 한국어 음성을 사용합니다. 재생이 안 되면 교사의 진단 화면에서 지시문을 두 번 읽어 줍니다. 서버에서 재생 횟수나 시험 감독을 보장하는 시스템은 아닙니다.

Solar 연결은 모의 응답으로 검증했습니다. 실제 키를 이용한 호출·제안 품질, 그림의 평가 타당도, 교사 간 채점 일치도는 별도 확인이 필요합니다.

- `backend/app/l3/`: 진단 근거를 사용하는 활동 생성·Solar 프롬프트·저장
- `src/pages/Diagnostic.tsx`, `TeacherDiagnostic.tsx`, `Roadmap.tsx`: 학생·교사 화면
- `backend/tests/test_diagnosis.py`: 설계안 예시 대조, 판정 경계, 조기 중단, 권한, 기존 기록 초기화, 저장·Solar 모의 검증
- `tests/workflows.spec.ts`: 학생 응답·교사 채점·학습 기록·모바일 브라우저 흐름

`npm run build`, `npm test`, `npm run test:e2e`로 검증합니다. 테스트는 개발 DB와 분리한 임시 DB를 사용합니다.
