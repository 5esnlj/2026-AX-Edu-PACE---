# Windows · VS Code에서 Solar 연결하기

Solar 연결은 브라우저 → 가나다계단 Python 서버 → Upstage API 순서로 작동합니다. API 키는 Python 서버의 `.env`에서만 읽습니다. 화면 코드나 `VITE_` 변수에 키를 넣지 마세요.

## 1. 수정된 코드 받기

VS Code에서 `package.json`이 있는 프로젝트 폴더를 열고 **터미널 → 새 터미널**을 선택합니다. 서버가 실행 중이면 `Ctrl+C`로 멈춥니다.

기존 `.env`가 있다면 먼저 프로젝트 바깥의 개인 폴더에 백업하세요. 이전 작업 브랜치에서는 `.env`가 GitHub에 포함되어 있었으며, 이번 브랜치는 이를 추적 대상에서 제거합니다. 실제 키를 넣어 올린 적이 있다면 Upstage 콘솔에서 폐기하고 새 키를 발급하세요. 이번 수정은 이전 커밋에 남은 파일까지 삭제하지 않습니다.

```powershell
git fetch origin
git switch feature/six-level-learning-path
git pull --ff-only origin feature/six-level-learning-path
```

로컬 수정 때문에 전환할 수 없다고 나오면 멈추고 메시지를 확인하세요. `reset --hard`로 덮어쓰지 마세요. 이 브랜치에는 기존 앱과 Solar 변경이 함께 들어 있습니다. GitHub `main`에 병합되기 전까지는 이 브랜치를 선택해 실행합니다.

## 2. 필요한 패키지 설치

```powershell
.\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt
npm.cmd install
```

`.venv` 폴더가 없다는 오류가 나오면 `py -m venv .venv`를 먼저 실행합니다. 이번 requirements에는 `python-dotenv`가 포함되어 있어 이전 `No module named 'dotenv'` 오류도 해결됩니다.

## 3. API 키 입력

[Upstage 콘솔](https://console.upstage.ai/)에서 API 키를 발급받습니다. 사용할 Solar 모델과 잔액·사용 권한도 콘솔에서 확인하세요.

프로젝트의 `.env.example` 파일을 복사해 `.env`라는 이름으로 저장합니다. 기존 파일이 없다면 터미널에서 아래 명령으로 만들 수 있습니다.

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

VS Code 왼쪽 파일 목록에서 `.env`를 열고 다음 값을 입력한 뒤 `Ctrl+S`로 저장합니다.

```dotenv
IEUM_AGENT_PROVIDER=solar
UPSTAGE_API_KEY=여기에_새로_발급받은_API_키
SOLAR_MODEL=solar-pro2
```

`UPSTAGE_API_KEY`의 안내 문구는 실제 키로 바꿉니다. 기본 모델은 `solar-pro2`이며, 계정에서 다른 모델을 제공하면 `SOLAR_MODEL`에 콘솔의 정확한 모델 ID를 넣습니다. 모델별 지원 여부는 계정과 제공 시점에 따라 다릅니다.

API 키를 채팅이나 GitHub에 올리지 마세요. `.env`는 이번 브랜치에서 Git 추적 대상에서 제외되며 `.env.example`에는 빈 키만 들어 있습니다. 시스템 환경 변수에 같은 이름이 설정되어 있으면 그 값이 `.env`보다 우선합니다.

## 4. 실행하고 실제 생성 확인

```powershell
npm.cmd run dev
```

1. 브라우저에서 `http://localhost:5173`을 엽니다.
2. **선생님이에요 → 데모 교실 입장하기**를 누릅니다.
3. 화면 아래 **Solar 사용 설정**을 확인합니다. 이는 키가 입력되었다는 뜻이며, API 인증·잔액 검사가 끝났다는 뜻은 아닙니다.
4. **맞춤 자료 만들기 → 예제 불러오기**를 선택합니다. 처음에는 대상 학생 1명으로 확인하세요.
5. **지원 방식 선택 → 학생별 자료 생성**을 누릅니다. 기본 L1 흐름에서는 **Solar가 생성한 교사용 L1 재구성 초안입니다**라는 안내로 실제 호출 결과를 확인합니다. [L1 프로필·검토 안내](teacher-l1-integration.md)를 참고하세요.
6. 학생별 글과 번역을 검토·수정하고 검토 완료 후 배포합니다.
7. **이해 확인 문항 만들기**를 누르면 해당 원문으로 Solar 문항 4개를 만듭니다.

처음부터 들어 있는 예제 자료·예제 문항은 규칙 기반 예시입니다. 설정을 바꿔도 기존 자료는 재생성되지 않습니다. 반드시 새 자료를 만들어 확인하세요. 같은 자료의 문항을 다시 요청하면 저장된 문항을 반환합니다.

브라우저 `http://localhost:5173/api/health`에서도 `provider: "solar"`, `configured: true`를 확인할 수 있습니다. 상태 확인은 유료 API를 호출하지 않으며 키를 반환하지 않습니다. `.env`를 바꾸면 `Ctrl+C` 후 서버를 다시 실행합니다.

실행만 하고 자동 갱신이 필요하지 않다면 다음 방법도 가능합니다.

```powershell
npm.cmd run build
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

이 경우 브라우저 주소는 `http://127.0.0.1:8000`입니다.

## 오류 안내

| 화면 메시지                      | 확인할 내용                                               |
| -------------------------------- | --------------------------------------------------------- |
| API 키가 없습니다                | 프로젝트 최상위 `.env`의 `UPSTAGE_API_KEY` 입력 후 재시작 |
| Solar 인증에 실패했습니다        | Upstage 키·모델 사용 권한, 폐기된 키 여부                 |
| Solar 사용 한도에 도달했습니다   | 콘솔의 잔액·호출 한도, 잠시 후 재시도                     |
| Solar 요청이 거절됐습니다        | 정확한 `SOLAR_MODEL` 이름과 권한, 원문 길이               |
| Solar 서버에 연결하지 못했습니다 | 인터넷·프록시에서 `api.upstage.ai` HTTPS 접근 허용        |
| 응답 시간이 초과됐습니다         | 원문·학생 수를 줄여 다시 시도                             |
| 필요한 자료 형식과 맞지 않습니다 | 불완전한 응답을 저장하지 않은 상태. 원문을 줄여 재시도    |

## 호출 범위와 검증

- L1 자료 생성은 학생별 원문·교과·규칙·어휘 사전·학습 지원 프로필을 전송합니다. 이름·학생 ID 필드는 제외하며, 원문이나 프로필 메모에 직접 포함한 내용은 전송됩니다. 기존 수동 방식은 원문·읽기 단계·언어·지원 방식을 전송합니다.
- 학생 1명당 자료 생성 1회, 자료별 문항 생성 1회가 호출됩니다. 자동 재시도는 없으며, 버튼으로 재시도하면 추가 비용이 발생할 수 있습니다. 한 학생의 생성이 실패하면 그 요청의 자료 전체를 저장하지 않습니다.
- **우리 반 수업 자료 → 오역 탐지 (L2)**도 같은 Solar 설정을 사용합니다. 검토 실행 1회당 호출 1회이며 교과·단원 선택 후 재실행도 추가 호출입니다. 본문·언어·교과·단원·참고 대역표를 전송합니다. 학생 ID·이름·자료 ID는 별도 필드로 전송하지 않으며 본문에 포함한 내용은 전송됩니다. [L2 사용 안내](teacher-l2-integration.md)를 참고하세요.
- JSON 구조, 문자열 길이, 4문항·3개 보기·정답 범위, 개념별 일반/쉬운 문항 쌍을 검사합니다. 내용의 정확성·번역 품질·문항 타당성은 별도 검토가 필요합니다.
- 기존 교과어 검토 화면의 단순 대역 비교, 학습 리포트 판정은 서버 규칙을 사용합니다. L3 배움길은 현재 6수준 진단으로 규칙 제안을 제공하고, 학생이 ‘Solar로 배움길 만들기’를 누르면 Solar를 호출합니다. Solar는 새 자료·자료 내 교과어·개념 카드·문항 생성과 L2 문맥 검토를 담당합니다.
- 자료의 교사 검토 후 배포 절차는 유지합니다. 문항은 현재 교사가 생성하면 바로 제공되는 구조이며, 별도의 문항 승인 단계는 후속 과제입니다.
- `npm test`는 모의 Solar 응답과 임시 DB를 사용하며 실제 키나 API 비용 없이 검증합니다. 브라우저 테스트는 강제로 demo 모드를 사용합니다.

실제 키를 사용한 Solar 호출 성공·번역 품질은 검증하지 않았습니다. 이 클라우드의 허용 도메인에는 `api.upstage.ai`가 포함되어 있지 않습니다. 위 4단계가 사용자 PC에서의 실제 연결 확인 절차입니다.

## 맞춤 자료 만들기에서 연결 상태 확인

화면 상단의 **Solar 연결 상태**는 앱 서버가 사용하는 모드·키 입력 여부·모델을 표시합니다. **Solar 실제 연결 확인**은 교사만 실행할 수 있으며, 수업 자료 없이 짧은 JSON 응답을 요청합니다(최대 출력 64토큰, 제한 시간 20초, 자동 재시도 없음). 소량의 호출 비용이 발생할 수 있습니다. 인증 실패·잔액/한도·모델 설정·접속 실패를 화면에 표시하며, 성공 표시는 확인 시점의 해당 모델 호출 성공입니다. 대량 자료 재구성 품질이나 이후 호출 성공을 보장하는 표시는 아닙니다.

클라우드의 .env는 PC로 복사되지 않습니다. PC에서 현재 ‘데모’ 안내가 나오면 해당 PC의 .env를 설정하고 서버를 재시작하세요. /api/health 주소 자체에 접속할 수 없으면 먼저 앱 실행 터미널의 Local 주소와 API 오류를 확인합니다. 열어 둔 화면은 서버 종료 후에도 남아 있을 수 있습니다.
