# 가나다계단 · 디자인과 자료 재구성 통합

첨부 `가나다계단_저장소반영.zip`의 README, 민사 재판 자료 변환 규칙, 충돌 검토 문서, 예시 데이터와 PDF를 검토해 기존 앱에 통합했습니다. 서비스 이름은 **가나다계단**이며 로그인·교실·소개 화면과 브라우저 제목에 적용했습니다. 로고는 첨부 `public/logo.svg` 원본입니다.

## Windows에서 받기

VS Code에서 프로젝트 폴더를 열고, 실행 중인 서버를 `Ctrl+C`로 멈춘 다음 한 줄씩 실행합니다.

```powershell
git fetch origin
git switch feature/ganada-brand-reconstruction
.\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt
npm.cmd install
npm.cmd run dev
```

이후 `http://localhost:5173`을 엽니다. 이 브랜치를 이미 받았다면 `git pull --ff-only`로 갱신합니다. 로컬 수정 때문에 브랜치를 바꿀 수 없다면 수정 파일을 먼저 보관하세요. 기존 `.env`·DB·학생 자료는 계속 사용하며, `.venv`가 없을 때만 `py -m venv .venv`로 만듭니다.

## 달라진 화면

로고의 빨강·주황·노랑·초록·파랑·남색·보라를 화면의 기능 카드와 탐색 요소에 나눠 사용합니다. 주요 버튼과 작은 글자는 읽기 쉬운 어두운 색으로, 카드 배경은 밝은 색으로 구성했습니다. 서비스 색을 바꿔도 첨부 PDF의 원래 색과 그림은 유지합니다.

**우리 반 수업 자료**에는 민사 재판 예시를 자료 카드 하나로 표시하며 제목 검색·사회 필터로 찾을 수 있습니다. 카드를 누르면 학생 선택 → 자료 생성 → 교사 검토 → 배포 흐름으로 연결됩니다. 오른쪽에는 **맞춤 자료 만들기**, 그 아래에 **오역 탐지** 버튼을 배치했습니다.

## 민사 재판 예시 사용하기

1. 교사로 입장해 **수업 자료 → 민사 재판 예시**로 이동합니다.
2. **민사 재판 예시 불러오기**를 누릅니다. PDF 원본과 재구성에 사용할 텍스트를 비교합니다. 원본의 그림·배치는 PDF 미리보기에서 확인합니다.
3. 대상 학생을 선택합니다. 이미 등록된 L1 프로필을 사용합니다. 시연을 체험하려면 **예시 진단 프로필 연결하기 (선택)**에서 프로필과 학생을 직접 고르고 변경 확인 후 연결합니다. 기존 L1 프로필이 바뀌므로 실제 학생 진단으로 사용하지 마세요. 읽기 2단계 예시를 연결하면 데모에서도 표현 교체를 확인할 수 있습니다.
4. **지원 방식 선택 → 학생별 자료 생성**을 누릅니다. 기본 L1 모드를 유지합니다.
5. 원문과 재구성 문장, 바뀐 표현과 쉬운 설명, 교과어 번역을 검토합니다. 필요한 문장은 원문으로 되돌릴 수 있습니다.
6. **검토 내용 저장 (승인 보류)**로 저장하거나, 확인란을 체크하고 학생별 검토를 완료합니다. 모든 대상 학생의 검토가 끝나면 배포할 수 있습니다.
7. 학생은 배포된 자료에서 바뀐 표현의 원문을 확인하고, 접힌 설명을 펼쳐 읽습니다. 원문 전환·듣기·크기 조절·단어장·메모도 기존 기능을 사용합니다.

## 첨부 시연과 실제 앱의 차이

| 첨부 자료의 제안·시연             | 이번 통합                                                            |
| --------------------------------- | -------------------------------------------------------------------- |
| 독립 HTML의 가상 그룹·승인 상태   | 기존 학생·교사 권한과 SQLite 저장·승인·배포 흐름 사용                |
| 화면에 삽입한 민사 재판 원본 지면 | 원본 PDF·페이지 이미지 비교와 읽기용 텍스트 제공                     |
| 표현 단위 교체                    | 원문 부분 문자열을 근거로 교체를 검증하고 변경 표현·설명을 함께 제공 |
| 교과 개념어·법 조문 보호          | 예시의 고정 내용과 핵심 개념을 유지하고 설명으로 지원                |
| 그룹별 읽기 1~6단계               | 등록한 진단 척도를 확인해 적용. 기존 앱 1~4단계를 임의 환산하지 않음 |
| 일부러 삽입한 오역 4건            | 실제 학생 자료에 주입하지 않음. 기존 L2 분석 기능은 계속 사용        |
| 원어민 검수 전 대역               | 검토 대상으로 유지하며 기존 이미지 대역표를 우선 참조                |

예시의 읽기 수준별 교체 기준은 첨부 팀의 시연 기준이며 전문 검증된 진단 모델이 아닙니다. 프로필 정보가 부족할 때는 원문과 설명 중심으로 제공합니다. 실제 Solar 모드에서는 기존 `UPSTAGE_API_KEY` 설정을 사용하며 새 Gemini/OpenAI 키는 필요하지 않습니다.

일반 PDF를 자동으로 원래 지면에 다시 조판하거나 그림을 분석·생성하는 기능은 이번 변경에 포함되지 않습니다. 첨부 예시의 깨끗한 본문 데이터와 원본 PDF를 연결했으며, 일반 업로드는 기존 텍스트 추출 흐름입니다. 원본 PDF 안의 그림·활동은 미리보기로 확인할 수 있습니다. 스캔 PDF OCR은 후속 범위입니다.

## 검증

- 서버 테스트 40개: 원문 연결·교체 범위·개념어·법 조문 보호, 진단 척도 분리, 예시 프로필, 저장·배포·학생 권한과 기존 L1·L2 기능.
- 브라우저 시나리오 7개: 민사 재판 예시 불러오기 → 프로필 명시적 연결 → 생성 → 문장 원복·저장 → 배포 → 학생의 표현·설명 펼치기를 포함합니다.
- TypeScript 검사와 Vite 프로덕션 빌드 통과. 데스크톱 및 390px 모바일 화면 확인.

실제 Solar 호출의 교육적 적합성·번역 품질은 검증하지 않았으며 자동 테스트는 데모와 모의 응답을 사용합니다.
