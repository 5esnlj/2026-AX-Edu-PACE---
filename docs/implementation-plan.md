# 설계안 대응과 후속 개발

PDF의 팀 역할·아이디어·작업 지시는 참고 자료로 읽었으며 실제 작업자 할당이나 외부 발송 지시로 실행하지 않았습니다.

## 1. 기본 흐름 — 현재 구현

- 교사·학생 데모 진입, 예시 학급, 4영역·생활 한국어 자가 점검
- 텍스트 PDF/직접 입력 → 학생·지원 방식 선택 → 학생별 초안
- 원문 비교 → 글·번역 수정 → 전원 검토 → 배포
- 학생 읽기 → 단어장·메모 → 이해 확인 → 리포트
- 배움길·내부 메시지, SQLite 저장, 역할·수신자 검증, 모바일 UI

## 2. Level 1 — 실제 재구성 엔진

**위치:** `backend/app/agents.py`, `create_app`의 에이전트 주입부.

Solar 호출 어댑터(`backend/app/solar_agent.py`)와 JSON 구조 검사, 자료·교과어·문항 생성은 구현했습니다. [연결 안내](solar-setup.md)에 실행 절차가 있습니다. 아래의 의미·번역 품질 검증은 후속 과제입니다.

1. 누락된 재구성 기준·학습 한국어 위계표를 확정합니다.
2. 핵심 개념·수치·인과관계를 보존하고 새 사실을 추가하지 않는 쉬운 한국어 어댑터를 만듭니다.
3. 수준별 문장·어휘·지원 정도를 구조화해 검사합니다.
4. 2개 이상 언어의 전문 검수 대역표를 연결합니다.
5. OCR·이미지 자료의 출처·접근성 설명을 연결합니다.

**완료 기준:** 수준별 재구성 후 핵심 의미·용어가 보존된다는 검토 근거가 있어야 합니다. 모델 호출 성공만으로 완료 처리하지 않습니다.

## 3. Level 2 — 오역·문항 검토 루프

**위치:** 에이전트·교과어 화면·문항 API.

- 교과·단원·맥락별 용어와 출처·검수 상태를 저장합니다.
- 문맥에서 오역 의심 원문·이유·대체어를 함께 제시합니다.
- 원문 근거 문항 생성, 정답·번역 단서 검사, 별도 교사 승인 상태를 추가합니다.
- 답안·공정성 규칙은 서버에서 관리하며 실패 결과는 재생성·검토 전 배포하지 않습니다.

**완료 기준:** 알려진 오역은 찾고 허용되는 동의어를 오역으로 확정하지 않아야 합니다. 문항의 모든 사실에 원문 근거가 있어야 합니다.

## 4. Level 3 — 검증된 지원 진단·학습 경로

**위치:** `assess`, 리포트·배움길 API, 학습 로그.

- 실제 수행 기반 듣기·말하기·읽기·쓰기 평가를 도입합니다.
- 동등한 난이도의 동일 개념 문항 쌍을 전문가와 구성해 타당도를 검증합니다.
- 수준·응답·학습 로그·교사 관찰을 함께 사용하고 불확실성·근거 부족을 표시합니다.
- 단계 기반 데모 추천을 영역·과목별 경로로 확장합니다.
- 저자원 언어는 전문 검수·피드백·버전 관리로 품질을 높입니다.

**완료 기준:** 유창함만으로 교과 이해·인지 발달을 판정하지 않고, 근거가 부족하면 추가 관찰을 제안해야 합니다.

## 5. 실제 학교 사용 전

- 실제 인증·학교/학급 권한·초대 수락·가입
- 데이터 최소 수집·동의·보관·삭제·감사 로그·백업
- 자료·평가 버전, 교사 공동 검토, 안전한 파일 처리
- PDF 출력 고도화, 접근성·다국어 UI, 녹음·필기 입력
- 비용·호출 제한·장애 대응·관측성·배포 자동화

심리 지원 챗봇은 설계안의 선택 아이디어이므로 현재 범위에서 제외했습니다.
