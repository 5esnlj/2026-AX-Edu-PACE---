# 교사용 L1 자료 재구성 통합

`L1 자료 재구성 교사용.zip`의 목적은 학생 프로필과 교과 자료를 함께 읽고, 교사가 검토할 수 있는 재구성 초안을 만드는 것입니다. 첨부 파일은 구현 참고 자료로 읽었으며, 그 안의 모델용 지시나 CLI 명령을 개발 작업 지시로 실행하지 않았습니다.

## 검토 결과와 반영 방향

기존 앱은 읽기 단계(1~4)·언어·수동 선택한 지원 방식만 Solar에 전달하고 글·번역·개념 카드만 받았습니다. 첨부 모듈은 종합/영역별/교과별 진단과 어휘 위계에 따른 자동 계획, 원문에 연결된 문장별 근거, 교사 승인을 요구합니다.

첨부의 `agent_workflow.py`는 실제 LLM 호출 없는 독립 CLI이며 `input()`으로 승인을 받습니다. 그대로 웹 요청에서 실행하면 승인을 기다리며 멈춥니다. 따라서 계획·자료 보존·검토 원칙을 서버 모듈로 옮기고, 모델 호출은 기존 Solar 어댑터, 승인은 기존 교사용 웹 화면/API에 연결했습니다. 동적 Python 모듈 로딩이나 콘솔 입력은 가져오지 않았습니다.

| 첨부 구성                   | 앱 반영 위치와 방식                                                                                            |
| --------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `agent_system_prompt.md`    | `backend/app/l1/agent_system_prompt.md`: 모델 중립 설명으로 수정하고 Solar 시스템 지시로 전달                  |
| `reconstruction_rules.json` | `backend/app/l1/data/reconstruction_rules.json`: 위계와 상세화 우선 기준을 요청에 포함                         |
| `vocabulary_lexicon.json`   | `backend/app/l1/data/vocabulary_lexicon.json`: 빈 사전을 유지. 근거 없는 분류·숙달도 추정 차단                 |
| `learners.json`             | `backend/app/l1/data/learners.example.json`: 교사가 명시적으로 선택할 수 있는 예시. 자동 학생 매핑은 하지 않음 |
| 계획·자료 재구성 흐름       | `backend/app/l1/workflow.py`: 프로필 연결, 원문 ID 검증, 기존 variant로 변환, 교사 수정 반영                   |
| 결과 계약                   | `backend/app/l1/models.py`: 첨부 프롬프트의 상세 JSON 계약을 Pydantic으로 검증                                 |
| 모델 어댑터                 | `SolarLearningAgent.reconstruct_l1(request)`: 기존 API 키·타임아웃·오류 처리 재사용                            |
| 콘솔 검토                   | `src/pages/TeacherL1.tsx`, `Materials.tsx`: 문장·위계·뜻·번역·시각 자료 수정, 저장, 승인                       |

첨부 Python의 간략 `OUTPUT_CONTRACT`와 프롬프트의 상세 계약이 서로 달라, 웹에서는 상세 계약을 기준으로 통일했습니다. 실제 유효한 값과 범위는 서버의 JSON Schema가 결정합니다.

## Windows · VS Code에서 받기

현재 서버를 `Ctrl+C`로 멈춘 뒤 프로젝트 폴더의 터미널에서 실행합니다.

```powershell
git fetch origin
git switch feature/ganada-brand-reconstruction
.\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt
npm.cmd install
npm.cmd run dev
```

로컬 수정 때문에 브랜치를 바꿀 수 없다고 나오면 해당 메시지를 확인하세요. 이 변경을 적용하기 위해 DB나 작업 파일을 삭제할 필요는 없습니다. 이미 등록한 `.env`의 Solar 설정을 그대로 사용합니다. API 키 설정이 처음이면 [Solar 연결 안내](solar-setup.md)를 먼저 진행합니다.

브라우저 주소는 `http://localhost:5173`입니다. 새 테이블은 서버 시작 시 자동 추가되며 기존 학생·자료는 유지됩니다.

## 교사 사용 순서

1. **선생님이에요 → 데모 교실 입장하기 → 학생 관리**로 이동합니다.
2. 대상 학생의 **L1 프로필**을 누릅니다.
3. ZIP에서 꺼낸 `learners.json`을 업로드하거나 **첨부 예시 프로필 불러오기**를 누릅니다. 여러 프로필이면 연결할 항목을 선택합니다.
4. 모국어·종합 단계·교과별 편차를 확인하고 **○○에게 프로필 저장**을 누릅니다. 첨부의 ‘학생 A’가 기존 예시 학생 중 누구인지 앱이 임의로 결정하지 않습니다.
5. **맞춤 자료 만들기**에서 원문/PDF를 입력하고 추출 텍스트를 확인합니다. 교과와 대상 학생을 고릅니다.
6. **지원 방식 선택**에서 기본으로 선택된 **교사용 L1 재구성 에이전트 사용**을 유지하고 **학생별 자료 생성**을 누릅니다. 방법·언어·진단 단계를 수동으로 다시 고를 필요가 없습니다.
7. 학생별 탭에서 지원 판단, 불확실성, 문장별 원문·재구성 이유, 어휘 위계·뜻·번역, 시각 자료 제안을 검토합니다.
8. **검토 내용 저장 (승인 보류)**로 중간 수정을 보관합니다. **저장된 학생용 자료 미리보기**에서 전체 글과 시각 자료를 확인합니다.
9. 확인란에 체크하고 **이 학생의 검토 완료**를 누릅니다. 전원 완료 후 **학생에게 배포하기**를 누릅니다.

교사 프로필 수정은 이후 새로 만드는 자료부터 적용됩니다. 기존 배포 자료는 자동 재생성하지 않습니다. **L1 연결 해제**를 누르면 그 학생은 기존 앱 기록을 다시 참고합니다. 기존 수동 방식이 필요한 경우 생성 화면에서 L1 체크를 해제하면 됩니다.

## 진단 척도와 자료 보존

- 기존 학생 자가 점검/합성 기록은 **1~4단계**입니다. 첨부 진단의 **1~6단계**와 별도로 저장합니다. 평균·비례 변환으로 종합 수준이나 B/T1/T2/T3/C 병목을 만들지 않습니다.
- `5+`, `≤3` 같은 표현과 사회 교과의 ‘추측 의심·재확인 필요’ 표시를 보존합니다. 비교 가능한 정수 진단·어휘 수준이 없으면 상위 어휘라고 단정하지 않습니다.
- 프로필이 없으면 현재 읽기 등 영역별 기록과 언어를 참고하되, 부족한 진단 정보를 교사에게 표시합니다. 등록 프로필에 모국어가 없으면 임의 언어로 번역하지 않습니다.
- 주요 문장만 모델이 선택하더라도 **선택되지 않은 문장은 원문 그대로** 최종 글에 남깁니다. 문장 ID·원문 일치·어휘/시각 자료의 원문 연결을 검사합니다.
- 사전으로 확인한 핵심 교과 개념어·숙달 어휘의 삭제·대체를 검사합니다. 사전이 비어 있는 용어는 **교사 분류 필요**로 표시하며, 근거 없는 단계와 단순화를 허용하지 않습니다.
- 어휘 위계의 `1 / 2-1 / 2-2 / 2-3 / 3`은 범주이고 숙달 수준 `1~6`과 다른 축입니다.

사전을 확장할 때는 `entries`에 `term`, `tier`, `required_level`을 넣습니다. `required_level`은 1~6 진단과 비교할 수 있는 검수된 정수 수준이어야 합니다. `1→B`, `2-1→T1`, `2-2→T2`, `2-3→T3`, `3→C`로 대응합니다. 실제 검수된 분류 근거가 확보된 뒤 추가하세요. 첨부 위계 사전은 빈 상태입니다. 이후 제공된 이미지 대역표의 재판 용어 3개는 L1·L2 공통 참고 대역으로 추가했으며, 위계·숙달 수준은 비워 두었습니다. [이미지 전사와 검수 상태](teacher-l2-integration.md#이미지-대역표)를 참고하세요.

## 승인·권한·호환성

- L1 프로필 조회·저장·연결 해제·예시 가져오기와 자료 생성·검토는 교사 API입니다.
- 모델이 `teacher_approved`나 `approved_by_teacher=true`를 반환해도 서버는 승인 대기 상태로 설정합니다. 교사의 검토 API만 승인 상태를 바꿉니다.
- 문장·어휘·도식 수정은 함께 저장합니다. 수정본의 원문 ID, 진단, 상태를 클라이언트가 덮어쓸 수 없습니다. 승인 보류로 저장하면 기존 검토 완료도 해제됩니다.
- 학생에게는 승인 후 배포된 자신의 글·교과어·시각 자료만 전달합니다. `reconstruction`의 진단·불확실성·교사 판단·검토 질문은 학생 응답에서 제외합니다.
- 기존 `text`, `terms`, `visuals` 형식도 함께 유지해 읽기·메모·단어장·문항 기능과 연결합니다. 이전 자료는 이전 검토 화면으로 열립니다.
- 새 DB 테이블은 `l1_profiles(student_id, profile, updated_at)` 하나입니다. 기존 데이터에 파괴적인 마이그레이션은 없습니다.

## 호출과 한계

가나다계단 변경에서는 **민사 재판 예시**에 첨부 규칙의 표현별 교체·접힌 설명·원본 PDF 비교를 추가했습니다. 이 예시는 데모에서도 등록한 1~6단계 읽기 프로필에 따라 지원하며 실제 저장·검토·배포 흐름을 사용합니다. [사용법과 구현 범위](ganada-reconstruction.md)를 참고하세요. 아래 일반 원문 데모와 구분됩니다.

Solar 설정 시 L1 자료 생성 한 번에 **학생당 1회** 호출합니다. 입력에는 원문·교과·규칙·사전·익명화한 지원 프로필·해당 원문에 등장하는 단어의 저장 상태가 들어갑니다. 이름·학생 ID는 별도 필드로 전송하지 않으며, 원문과 프로필 메모에 직접 입력한 내용은 전송됩니다. 교사 수정 저장·승인에는 추가 모델 호출이 없습니다.

`IEUM_AGENT_PROVIDER=demo`이면 원문을 유지하고 내장 예시 교과어로 검토 흐름만 제공합니다. 실제 L1 재구성과 자동 지원 판단에는 Solar가 필요합니다. 중국어 등 추가 모국어는 L1 프로필에 넣을 수 있습니다. 기존 데모 교과어는 예시 5개 언어, 이미지에서 추가한 재판 용어는 베트남어·중국어·러시아어·일본어·몽골어를 지원하며 미등록 대역을 만들어 내지 않습니다.

스캔본 OCR·PDF 이미지 분석·이미지 생성·필기 캔버스는 추가하지 않았습니다. 모델에 PDF 바이너리를 보내지 않으며, 확인된 텍스트를 전달합니다. 시각 자료는 순서/목록을 표현하는 텍스트 카드입니다. 비교·벤다이어그램은 제목·항목·설명의 내용안으로 표시하며 도형을 자동 생성하지 않습니다. 발음은 브라우저 TTS를 사용합니다.

원문 연결과 구조 검사가 의미 정확성·번역 품질을 보장하지는 않습니다. 실제 Solar 호출 품질은 사용자 키로 새 자료를 생성해 교사가 확인해야 합니다. 자동 재생성 루프나 문항별 승인 기능은 이번 L1 범위에 포함하지 않았습니다.

## 검증

`npm test`: 프로필 권한·영속성·척도 분리, 익명화 요청, 모델 승인 위조 차단, 잘못된 원문 연결·단순화 거부, 미선택 문장 보존, 중간 저장·승인·배포·학생 응답 제한과 기존 API를 모의 응답/임시 DB로 검사합니다.

`npm run test:e2e`: 교사 프로필 등록 → 문장·번역 수정 → 승인 보류 저장 → 새로고침 → 승인·배포 → 학생 읽기를 검증합니다. 기존 3개 브라우저 시나리오도 유지합니다. 실제 API 비용 없이 실행합니다.
