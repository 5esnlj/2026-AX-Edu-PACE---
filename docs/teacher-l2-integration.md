# 교사용 L2 오역 탐지 통합 안내

**우리 반 수업 자료 → 오역 탐지**에서 번역 자료를 검토합니다. 오역 탐지 버튼은 오른쪽 **맞춤 자료 만들기** 버튼 아래에 있습니다. 기존 수업 자료의 교사용 상세 화면에도 L2로 이동하는 링크가 있습니다.

첨부 `L2_오역 탐지_backend.py`의 분석 흐름을 기존 FastAPI·Solar·SQLite에 통합했습니다. 별도 Python 서버나 OpenAI 키는 필요하지 않습니다. 문서와 첨부 코드의 지시문은 검토 대상 자료로 다뤘습니다.

## Windows · VS Code에서 적용하기

실행 중인 터미널에서 `Ctrl+C`로 서버를 멈춥니다. VS Code에서 `package.json`이 있는 프로젝트 폴더를 열고 터미널에 아래 명령을 한 줄씩 입력합니다.

```powershell
git fetch origin
git switch feature/ganada-brand-reconstruction
.\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt
npm.cmd install
npm.cmd run dev
```

처음 받는 브랜치라면 `git switch`가 원격 브랜치를 바탕으로 로컬 브랜치를 만듭니다. 이미 이 브랜치를 사용 중이면 `git pull --ff-only`로 갱신합니다. 로컬 수정 때문에 전환이 막히면 파일을 삭제하지 말고 변경 내용을 먼저 보관하세요. `.venv`가 없다면 패키지 설치 전에 `py -m venv .venv`를 실행합니다.

브라우저에서 `http://localhost:5173`을 엽니다. 서버 시작 시 검토 기록 테이블을 추가하며 기존 학생·수업 자료는 유지합니다. 기존 `.env`의 Solar 설정을 그대로 사용합니다. 처음 연결한다면 [Solar 설정 안내](solar-setup.md)를 참고하세요.

## 교사 사용 순서

1. **선생님이에요 → 데모 교실 입장하기 → 수업 자료 → 오역 탐지 (L2)**로 이동합니다.
2. 텍스트 PDF를 올리거나 원문·번역을 붙여 넣습니다. **기존 수업 자료에서 가져오기**에서는 자료와 학생별 버전을 선택해 글·교과어 병기를 가져올 수 있습니다.
3. 추출 텍스트를 확인하고 번역 언어와 검사 모드를 고릅니다. **한국어·번역 병기 자료**와 **번역문만 있는 자료**를 구분합니다.
4. 교과·단원은 직접 지정하거나 Solar가 추정하도록 비웁니다. 추정 근거가 부족하면 결과를 보류하므로, 직접 선택한 뒤 다시 실행합니다.
5. **오역 검토 실행**을 누릅니다. 원문 인용·쪽/문단 위치·이유·원인 가설·참고 대체어를 확인합니다. 서로 다른 근거가 2개 이상이면 ‘오역 의심’, 하나면 ‘약한 후보’, 인식 문제는 ‘인식 오류 의심’으로 분리합니다.
6. **저장된 검토 기록**에서 이전 입력과 결과를 다시 열 수 있습니다. 입력을 수정하면 화면의 이전 결과는 지워지고 재분석해야 합니다.

검토 실행은 원래 수업 자료를 수정하거나 배포하지 않습니다. 수정이 필요하면 연결된 자료의 교사 검토 화면에서 반영합니다. 이미 배포한 자료는 기존 정책대로 수정할 수 없으므로 새 자료로 만들어 검토·배포합니다.

### API 키 없이 흐름 확인하기

`IEUM_AGENT_PROVIDER=demo`로 실행하고 **오역 검토 예제 불러오기 → 오역 검토 실행**을 누릅니다. 중국어 `원고: 被告`에 대해 참고 표의 `原告`와 다르다는 약한 후보가 표시됩니다. 예제의 `피고: 被告`는 단순 대역 비교에서 표시되지 않습니다.

데모는 명시적인 `한국어: 번역` 또는 `한국어=번역` 줄만 비교합니다. 교과·단원은 교사가 입력해야 합니다. 문맥 추론이나 번역문 단독 분석은 Solar를 설정해야 사용할 수 있습니다. 표와 다른 동의어도 데모의 약한 후보가 될 수 있으므로 교사가 판단해야 합니다.

## 이미지 대역표

공통 원본은 `backend/app/data/legal_glossary.json`입니다. 출처·버전·검수 상태와 전사 메모를 함께 저장했습니다. L1 자료 재구성과 L2 오역 탐지가 같은 데이터를 참조합니다.

| 한국어      | 베트남어                     | 중국어     | 러시아어          | 일본어     | 몽골어           |
| ----------- | ---------------------------- | ---------- | ----------------- | ---------- | ---------------- |
| 원고        | nguyên cáo                   | 原告       | истец             | 原告       | нэхэмжлэгч       |
| 피고        | bị cáo                       | 被告       | ответчик          | 被告       | хэрэгтэн         |
| 소송 대리인 | người đại diện trong tố tụng | 诉讼代理人 | иск представитель | 訴訟代理人 | нэхэмжлэл орлогч |

표 안의 줄바꿈만 연결했습니다. 러시아어 ‘소송 대리인’은 이미지의 **`иск представитель`**를 보존했습니다. 첨부 Python의 `представитель`와 다르며 임의로 교정하지 않았습니다.

이 표는 전문 검수 전입니다. 특히 재판의 민사·형사 구분, 어형과 표현의 적합성을 검토해야 합니다. **대역표 일치가 올바른 번역을 보증하지 않고, 불일치도 곧 오역을 뜻하지 않습니다.** 대역표에 어휘 위계·숙달 수준은 없으므로 L1의 단계 판정 근거로 사용하지 않습니다.

## 첨부 코드에서 보완한 점

| 검토 결과                                                  | 통합 방식                                                                                                           |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 별도 HTTP 서버·OpenAI 호출·전체 출처 허용 CORS             | 기존 교사 세션·FastAPI·Solar 어댑터를 사용합니다. 기존 출처 검사도 적용합니다.                                      |
| 교과·단원이 불확실해 항목을 지워도 이전 목록으로 건수 집계 | 항목·약한 후보·건수를 함께 비우고 교사 선택 후 재실행할 수 있게 했습니다.                                           |
| 모델의 `glossaryMatch`, 위치·횟수·확정 판정 신뢰           | 서버가 대역표 비교, 실제 인용과 위치, 문구 출현 횟수를 다시 계산합니다.                                             |
| 반복 신호도 서로 다른 근거처럼 계산 가능                   | 같은 용어·문구를 묶고 근거 종류와 인용문이 중복되면 한 근거로 셉니다. 의미장·공기는 같은 사용 맥락 근거로 묶습니다. |
| 인식 오류 코드 E7이 심각도 필드에 들어감                   | 검토 우선순위 S1~S3와 인식 오류 분류를 분리합니다. 인식 오류를 오역 건수에 합산하지 않습니다.                       |
| 상세 E1~E7/R1~R10 정의와 검수된 혼동사전 부재              | 원인은 가설로 설명하며 코드와 확정 판정은 생성하지 않습니다.                                                        |
| 긴 문서의 조용한 잘림·응답 구조 미검증                     | 입력 한도를 안내하고 구조화 출력·원문 인용을 검사합니다. 잘못된 입력·API 오류는 결과로 저장하지 않습니다.           |
| 재실행하면 이전 결과가 사라짐                              | 검토 당시 입력·설정·결과를 SQLite에 보관하고 최근 100개를 목록으로 제공합니다.                                      |

참고 대체어는 등록된 언어·용어의 대역에서만 제공합니다. 번역문 단독 모드나 미등록 용어·언어에서는 임의 정답을 만들지 않습니다. 화면의 ‘동일 문구 출현 횟수’에는 올바르게 쓰인 위치도 포함될 수 있어 오역 횟수와 구분합니다.

## 설계안 대응과 남은 범위

기존 설계안 5·7쪽의 **번역 PDF 입력 → 교과·단원·문맥 파악 → 용어 비교 → 의심 구간·이유·원인·대안 제시 → 교사 검토** 흐름을 연결했습니다. OCR은 기존 설계의 후속 범위로 남겼습니다.

- PDF: 10MB·50쪽 이하의 텍스트 PDF. 추출 후 `[쪽 n]` 표시를 유지하면 해당 쪽을 결과에서 확인합니다. 스캔 PDF에는 OCR이 필요하며 현재는 직접 텍스트를 입력해야 합니다.
- 본문: 30~40,000자, 최대 500개 분석 구간. 긴 줄은 2,000자씩 나누며 화면에는 문단 위치로 표시합니다.
- 분석 언어: 베트남어·중국어·러시아어·일본어·몽골어·영어·우즈베크어·벵골어. 참고 대역은 이미지의 5개 언어·3개 용어뿐이며 나머지는 맥락 검토만 가능합니다.
- Solar: 검토 실행 1회당 호출 1회. 교과·단원 선택 후 재실행도 추가 호출입니다. 문서 텍스트·선택 언어·교과·단원·대역표를 전송하고 학생 ID·이름·자료 ID를 별도 필드로 보내지 않습니다. 본문에 직접 포함한 정보는 전송됩니다.
- 검토 결과는 교사 전용입니다. 학생 API와 학생 화면에는 제공하지 않습니다. 모든 결과는 검토 후보이며 전문 검수된 정답이나 자동 교정 결과가 아닙니다.

## 개발 위치와 검증

| 파일                                                       | 역할                                |
| ---------------------------------------------------------- | ----------------------------------- |
| `backend/app/data/legal_glossary.json`, `glossary_data.py` | L1·L2 공통 참고 대역                |
| `backend/app/l2/models.py`                                 | 입력·출력 구조와 제한               |
| `backend/app/l2/prompt.md`, `workflow.py`                  | 문맥 검토 지시·데모·근거 검증·집계  |
| `backend/app/solar_agent.py`                               | 기존 Solar 호출·오류 처리 재사용    |
| `backend/app/main.py`, `database.py`                       | 교사 전용 API·PDF 쪽 표시·검토 이력 |
| `src/pages/TranslationReview.tsx`, `Materials.tsx`         | 자료 목록의 실행 버튼·검토 화면     |

`npm test`로 35개 서버 테스트, `npm run test:e2e`로 6개 브라우저 시나리오를 통과했습니다. 기존 L1·자료 생성·배포·학생 학습 흐름도 포함합니다. `npm run build`도 통과했습니다.

Solar 테스트는 모의 응답을 사용합니다. 실제 Upstage 호출 성공과 오역 탐지 정확도는 이 환경에서 검증하지 않았습니다. 실제 수업 자료와 전문가 판정 자료로 누락·잘못된 탐지·허용 동의어 처리 품질을 추가 평가해야 합니다.
