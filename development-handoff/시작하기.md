# 가나다계단 FE·API 검토 수정본

첨부된 React 소스와 이전 API를 대조해 만든 **별도 개발용 수정본**입니다. 기존 파일과 DB를 덮어쓰지 않았고 GitHub에 push하지 않았습니다.

## 먼저 볼 파일

1. `API_CHANGES.md`: API와 화면 데이터 연결에서 무엇이 바뀌었는지.
2. `FRONTEND_API_REVIEW.md`: 원본 코드의 정확한 위치와 검토 근거.
3. `api/API_SPEC.html`: 브라우저로 열어 보는 최신 API 명세. `api/openapi.json`은 개발 도구용입니다.
4. `DEVELOPMENT_PLAN.md`: 실제 교육 현장용 웹앱까지 남은 작업·순서·완료 기준.
5. `VERIFICATION.md`: 이번 검증 결과와 검증하지 않은 범위.

수정한 화면 코드는 `frontend/`, HTTP mock 코드는 `api/`에 있습니다. 원본 비교용 코드도 `frontend-original/ganada-frontend/`에 보존했습니다. 실행할 때는 **frontend 폴더**를 사용하세요.

## Windows에서 직접 확인

Python 3.11 이상과 Node.js 22 LTS 또는 24 LTS가 설치된 PC에서 확인합니다. ZIP을 별도 폴더에 풀고, VS Code에서 **이 문서와 frontend·api 폴더가 함께 있는 폴더**를 엽니다. 터미널은 두 개 필요합니다.

첫 번째 PowerShell 터미널에서 API를 켭니다. 아래 명령은 한 줄씩 입력합니다.

```powershell
cd api
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn mock_server:app --host 127.0.0.1 --port 8081
```

이 창은 켜 두세요. 가상환경 활성화 스크립트를 실행할 필요는 없습니다.

VS Code의 **터미널 → 새 터미널**로 두 번째 창을 열고, 이 문서가 있는 폴더에서 시작합니다. 새 창이 api 폴더에서 열렸다면 `cd ..`로 한 단계 올라온 뒤 아래 명령을 실행하세요.

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

브라우저에서 **http://localhost:5173**을 엽니다. 프론트가 `/api/v1` 요청을 첫 번째 터미널의 8081 서버로 전달합니다. 별도로 Solar 키나 DB 비밀번호를 입력하지 않습니다. 포트가 사용 중이면 해당 포트로 실행한 이전 개발 서버를 종료하고 다시 실행하세요.

| 로그인 역할 | 아이디 | 확인 내용 |
|---|---|---|
| 교사 | `t_math` | 수학 담당 교사 대시보드·원본 자료 목록 |
| 교사 | `t_science` | 같은 반 과학 담당 교사: 수학 자료는 제외 |
| 학생 | `s_a` | 진단 완료 학생의 대시보드·선택 영역 수준 |
| 학생 | `s_pending` | 진단 미완료 안내와 학습 화면 진입 제한 |
| 학생 | `s_new` | 클래스 참여 필요 안내 |

비밀번호는 모두 **mock-pass-123**입니다. 모두 가상 사용자입니다. 다른 역할을 확인할 때는 로그아웃한 뒤 새로 로그인하세요. 실제 서비스에서는 이 가상 로그인 UI와 계정을 운영 계정 기능으로 교체해야 합니다.

API 요청 구조는 **http://127.0.0.1:8081/docs**에서도 확인할 수 있습니다. `/docs`와 웹앱을 서로 다른 호스트명으로 열면 쿠키가 공유되지 않을 수 있으므로 각각 로그인하세요.

## 무엇을 확인할 수 있나

- 원본의 세 화면을 서버 응답으로 표시: 교사 대시보드, 교사 자료 목록, 학생 대시보드.
- 클래스명·사용자·검토 대기 수·진단 수준·자료가 API에서 표시되는지.
- 초급 미달/초급/중급/고급과 진단 미완료를 구분하는지.
- 교사는 해당 클래스 담당 교과의 원본만 보는지.
- 학생의 선택 영역을 바꿀 때 해당 영역의 듣기·읽기 결과가 표시되는지.
- 로딩·오류·빈 목록과 미구현 기능 안내가 있는지.

생성·검토·배포·풀이 등의 API 계약은 mock 서버에 있지만, 그 화면들은 아직 이 FE에 조립하지 않았습니다. 따라서 해당 버튼은 동작 완료처럼 보이지 않도록 비활성화했습니다. 진단·클래스 가입 화면도 다음 개발 단계입니다.

## 개발자가 실행할 검사

`api` 폴더에서:

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_api test_frontend_contract
.\.venv\Scripts\python.exe capture_examples.py
.\.venv\Scripts\python.exe validate_examples.py
```

`frontend` 폴더에서:

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run check:hardcode
```

API는 메모리 mock입니다. 재시작하면 변경 데이터가 사라지며 실제 MariaDB·Solar·PDF 추출·공식 진단 음원을 사용하지 않습니다. 이번 작업으로 운영 서버가 배포된 것은 아닙니다. 기존 DDL·DML은 `api/baseline/`에 보존했고 후속 개발에서 연결합니다.
