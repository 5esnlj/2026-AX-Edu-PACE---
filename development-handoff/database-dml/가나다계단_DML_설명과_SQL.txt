가나다계단 기능별 DML 초안

기준: 개발 계획.pdf 2쪽, 확정된 MariaDB 11.8용 20개 테이블, 이후 변경한 ‘교사는 해당 클래스에서 자기 교과 자료만 조회’ 요구. 2026-11-21.

DDL은 테이블을 만드는 문장이고, DML은 만들어진 테이블에 데이터를 넣고(INSERT), 조회하고(SELECT), 수정하고(UPDATE), 삭제하는(DELETE) 문장입니다. 여기서는 SELECT도 기능 설명에 함께 포함합니다. 이 문서는 백엔드 개발용 텍스트이며 전체를 순서대로 실행하는 설치 SQL이 아닙니다. 기존 앱이나 사용자 PC의 DB에는 실행하지 않습니다.

먼저 정할 실행 규칙

- :actor_id 같은 표기는 서버가 값을 바인딩하는 매개변수입니다. HeidiSQL에서 그대로 실행할 수 없습니다. 실제 드라이버의 ? 또는 %s 등에 맞춥니다. 문자열로 이어 붙이지 않습니다.
- :actor_id, 역할, 채점 점수, 정답 여부, API 키 소유자, 버전 순번은 브라우저가 정하지 않습니다. 인증된 서버가 결정합니다. 다른 ID는 요청에서 받더라도 소속/배정 관계를 검증합니다.
- 매 요청마다 아래 A01로 세션을 검증합니다. 교사는 실제 teacher 계정이고 확인된 계정이어야 합니다. ‘교사 로그인’ 화면 선택만으로 역할이 생기지 않습니다.
- 쓰기 흐름은 START TRANSACTION → 권한 확인 및 필요한 행 FOR UPDATE → 조건 분기 → INSERT/UPDATE → COMMIT입니다. 조건 불충족·영향 행 수 불일치·예외는 ROLLBACK 후 중단합니다. SQL SELECT 자체가 다음 문장의 실행을 막지는 않으므로 이 분기를 반드시 서버 코드로 구현합니다.
- 아래 B01/C01 같은 번호는 실행 전제의 참조입니다. ‘B01 통과 후’는 동일 요청에서 실제로 그 조회를 실행하고 반환 행을 확인한다는 뜻입니다. 쓰기는 동일 트랜잭션에서 필요한 행을 잠급니다. 인증/소속을 전역 변수에 캐시해 재사용하지 않습니다.
- 한 트랜잭션은 같은 DB 연결로 실행합니다. 커넥션 풀에서 도중에 연결을 바꾸지 않습니다. 새 ID는 INSERT가 정확히 1행 성공한 직후 같은 연결의 LAST_INSERT_ID()로 받습니다. 잠금은 일정한 순서로 잡고 교착 상태가 나면 동일 요청키로 전체 트랜잭션을 제한적으로 재시도합니다.
- 읽기 화면은 SELECT만 실행합니다. 긴 Solar 호출이나 파일 업로드 중에는 DB 트랜잭션을 열어 두지 않습니다.
- 교사별 담당 교과는 클래스마다 1개, 학생 진단은 계정당 1회입니다. 자료의 교과는 원본에서 유도합니다. 소유자도 다른 교과 자료 열람 예외는 없습니다.
- 자료 초안 수정·검토·배포는 같은 교과 조건에 더해 ‘작성자 또는 클래스 소유자’를 기본 정책으로 사용합니다. 교사 초대는 소유자, 학생 초대는 활성 교사에게 허용합니다.
- 연결은 UTC를 사용합니다. 애플리케이션에서 한국 시각으로 표시합니다.

자주 쓰는 매개변수는 다음과 같습니다. student_id는 사용자 계정 ID이고 student_member_id는 특정 클래스의 소속 ID이므로 혼용하지 않습니다.

| 매개변수 | 출처/뜻 |
|---|---|
| :actor_id | 세션에서 확인한 현재 사용자 users.id |
| :class_id | 접근하려는 클래스 classes.id |
| :student_member_id | 대상 학생의 class_memberships.id |
| :source_material_id | 출처 원본 source_materials.id |
| :student_material_id | 학생별 전환본 student_materials.id |
| :quiz_id / :question_id | 문제 묶음 / 해당 묶음의 개별 문제 |
| :expected_updated_at | 화면에서 읽은 버전 시각. DB 값과 다르면 충돌 처리 |
| :request_key | 같은 논리 요청의 재전송을 구분하는 키. 재시도 시 유지 |

트랜잭션의 서버 제어 흐름은 아래와 같습니다. 이 의사코드는 SQL 문장이 아닙니다.

연결에서 START TRANSACTION 실행
인증·소속·대상 행 확인 및 잠금
조건을 만족하지 않으면 ROLLBACK하고 오류 응답
해당 기능의 INSERT/UPDATE 실행
예상한 저장 결과가 맞으면 COMMIT하고 성공 응답
예외가 발생하면 ROLLBACK하고 중단

실제 SQL과 단계별 분기는 아래 기능 번호를 따라갑니다. 각 SQL 블록은 독립 명령 또는 명시된 트랜잭션의 일부입니다.

A. 계정과 로그인

A00. 계정 등록과 로그인 대상 조회

등록 시 비밀번호는 서버에서 Argon2id 등으로 해시합니다. 교사 신규 가입은 pending, 검증 완료 뒤 서버의 승인 절차로 active/teacher_verified_at을 설정합니다. 학생 active 전환은 가입 확인 정책을 통과한 뒤 서버가 수행합니다. 일반 회원 API에 교사 승인 SQL을 노출하지 않습니다.

INSERT INTO users
  (login_id, role, password_hash, display_name, email, native_language_code, status)
VALUES
  (:login_id, :validated_role, :password_hash, :display_name, :email, :language_code, 'pending');

SELECT id, role, password_hash, status, teacher_verified_at
FROM users
WHERE login_id = :login_id AND role = :selected_login_role AND deleted_at IS NULL;

서버가 비밀번호와 active 상태를 검증한 후에만 세션을 저장합니다. 비밀번호 해시는 브라우저로 반환하지 않습니다. 원문 세션 토큰은 안전한 난수로 생성하고 DB에는 SHA-256 32바이트 해시만 저장합니다. 로그인 응답으로 HttpOnly 쿠키를 설정하는 작업은 서버 기능입니다.

INSERT INTO user_sessions (user_id, token_hash, expires_at)
SELECT id, :token_hash, :expires_at
FROM users
WHERE id = :verified_user_id AND status = 'active' AND deleted_at IS NULL
  AND (role = 'student' OR teacher_verified_at IS NOT NULL);

A01. 세션 확인 / 로그아웃

이 조회에서 얻은 id를 이후 :actor_id로 사용합니다. 학생은 진단이 completed인지 확인해서 미완료라면 진단 화면으로 이동시키고 학습 API도 동일하게 제한합니다. 가입할 클래스가 없다면 초대 수락 화면을 먼저 제공합니다.

SELECT u.id, u.role, u.display_name, u.native_language_code
FROM user_sessions ss JOIN users u ON u.id = ss.user_id
WHERE ss.token_hash = :token_hash AND ss.revoked_at IS NULL
  AND ss.expires_at > UTC_TIMESTAMP(6)
  AND u.status = 'active' AND u.deleted_at IS NULL
  AND (u.role = 'student' OR u.teacher_verified_at IS NOT NULL);

UPDATE user_sessions SET revoked_at = UTC_TIMESTAMP(6)
WHERE token_hash = :token_hash AND user_id = :actor_id AND revoked_at IS NULL;

B. 클래스와 초대

B00. 내 클래스 목록 / 교사의 클래스 개설

교사와 학생이 같은 목록 조회를 사용하되 역할에 따라 화면을 다르게 보여 줍니다.

SELECT c.id, c.name, c.grade_label, c.academic_year,
       m.role, m.teacher_subject_code
FROM class_memberships m JOIN classes c ON c.id = m.class_id
WHERE m.user_id = :actor_id AND m.status = 'active' AND c.status = 'active'
ORDER BY c.created_at DESC, c.id DESC;

개설은 아래 3문장을 한 트랜잭션으로 묶습니다. 첫 INSERT 1행 성공을 확인하고 ID를 받습니다. 마지막 INSERT가 실패하면 클래스 생성도 취소합니다. :approved_subject는 5개 교과 코드 중 서버가 검증한 값입니다.

INSERT INTO classes (owner_teacher_id, name, grade_label, academic_year)
SELECT id, :class_name, :grade_label, :academic_year
FROM users WHERE id = :actor_id AND role = 'teacher' AND status = 'active'
  AND teacher_verified_at IS NOT NULL AND deleted_at IS NULL;

SELECT LAST_INSERT_ID() AS new_class_id;

INSERT INTO class_memberships (class_id, user_id, role, teacher_subject_code)
VALUES (:new_class_id, :actor_id, 'teacher', :approved_subject);

B01. 클래스 교사 권한 확인

조회 화면은 FOR UPDATE를 생략합니다. 초대·자료 생성 같은 쓰기는 트랜잭션 안에서 실행합니다. 0행이면 중단합니다. 담당 교과 변경/퇴출도 같은 소속 행을 잠그도록 구현합니다.

SELECT c.id, c.owner_teacher_id, m.id AS teacher_member_id, m.teacher_subject_code
FROM classes c
JOIN class_memberships m ON m.class_id = c.id
JOIN users u ON u.id = m.user_id
WHERE c.id = :class_id AND c.status = 'active'
  AND m.user_id = :actor_id AND m.role = 'teacher' AND m.status = 'active'
  AND u.role = 'teacher' AND u.status = 'active' AND u.teacher_verified_at IS NOT NULL
  AND u.deleted_at IS NULL
FOR UPDATE;

B02. 초대 발급

B01 통과 후 실행합니다. 학생 초대는 teacher, 교사 초대는 owner가 발급하도록 조건을 둡니다. 랜덤 초대 토큰 원문은 링크에 넣고 DB에는 해시만 저장합니다.

INSERT INTO class_invitations
 (class_id, invited_role, created_by_user_id, token_hash, expires_at, max_uses)
SELECT c.id, :invited_role, :actor_id, :invite_token_hash, :expires_at, :max_uses
FROM classes c WHERE c.id = :class_id AND c.status = 'active'
  AND (:invited_role = 'student'
       OR (:invited_role = 'teacher' AND c.owner_teacher_id = :actor_id));

B03. 초대 수락

하나의 트랜잭션에서 진행합니다. 같은 사용자의 동시 가입은 users 행을 먼저 잠가 직렬화합니다. 계정의 role과 초대의 invited_role이 일치해야 하며 교사 계정은 검증 완료여야 합니다.

SELECT id, role, teacher_verified_at FROM users
WHERE id = :actor_id AND status = 'active' AND deleted_at IS NULL
FOR UPDATE;

SELECT i.id, i.class_id, i.invited_role, i.expires_at, i.max_uses, i.used_count
FROM class_invitations i JOIN classes c ON c.id = i.class_id
WHERE i.token_hash = :invite_token_hash AND c.status = 'active'
  AND i.revoked_at IS NULL AND i.expires_at > UTC_TIMESTAMP(6)
  AND i.used_count < i.max_uses
FOR UPDATE;

SELECT id, role, status FROM class_memberships
WHERE class_id = :invited_class_id AND user_id = :actor_id
FOR UPDATE;

이미 active이면 ‘이미 가입됨’으로 종료하고 used_count를 올리지 않습니다. left/removed이면 자동 복귀시키지 않고 소유자의 재가입 승인 흐름으로 처리합니다. 새 가입일 때만 아래 두 문장을 실행하며 각각 1행이어야 COMMIT합니다. 교사의 :approved_subject는 소유자 승인 값이어야 합니다. 현재 초대 테이블에는 담당 교과가 없으므로 학생 초대처럼 링크 클릭만으로 임의 교과 권한을 부여하지 않습니다.

INSERT INTO class_memberships
 (class_id, user_id, role, teacher_subject_code, invitation_id, roster_number)
VALUES (:invited_class_id, :actor_id, :verified_account_role,
        :approved_subject_or_null, :invitation_id, :student_number_or_null);

UPDATE class_invitations SET used_count = used_count + 1
WHERE id = :invitation_id AND revoked_at IS NULL
  AND expires_at > UTC_TIMESTAMP(6) AND used_count < max_uses;

초대 횟수만 먼저 증가시키거나 가입 실패 후 COMMIT하면 안 됩니다. 마지막 UPDATE가 0행이면 가입 INSERT도 ROLLBACK합니다.

현재 20개 테이블에는 ‘초대 링크에 지정된 교과’ 컬럼이 없습니다. 따라서 공동 교사의 담당 교과는 소유자가 확인·승인하는 서버 절차를 전제로 합니다. 학생 가입은 자동 처리할 수 있습니다. 교사도 링크 수락만으로 지정 교과에 자동 가입하게 만들려면 추후 class_invitations에 담당 교과 컬럼을 추가하고 발급 시 소유자가 정하도록 보완해야 합니다. 이번 DML에서 이 값을 교사 본인이 마음대로 확정하도록 처리하지 않습니다.

C. 최초 진단과 중간 저장

C00. 최초 진단 생성

A01의 학생 계정만 실행합니다. 트랜잭션에서 users의 해당 학생 행을 FOR UPDATE로 잠근 뒤 기존 진단을 조회합니다. 이미 존재하면 재생성하지 않고 기존 form_id를 사용합니다. 첫 생성에 사용하는 문항집 ID는 서버가 정한 현재 공개 버전입니다.

SELECT id FROM users WHERE id = :actor_id AND role = 'student' AND status = 'active'
FOR UPDATE;

SELECT student_id, form_id, status, completed_at
FROM student_diagnostics WHERE student_id = :actor_id;

기존 진단이 없을 때만 다음을 실행합니다. 참가 클래스가 없거나 문항집이 미공개이면 생성되지 않습니다.

INSERT INTO student_diagnostics (student_id, form_id, origin_class_id)
SELECT m.user_id, f.id, m.class_id
FROM class_memberships m
JOIN classes c ON c.id = m.class_id AND c.status = 'active'
JOIN diagnostic_forms f ON f.id = :active_form_id AND f.status = 'published'
WHERE m.class_id = :class_id AND m.user_id = :actor_id
  AND m.role = 'student' AND m.status = 'active';

C01. 진단 제출 권한·상태 잠금

매 답안 저장 트랜잭션에서 실행합니다. 0행이면 중단합니다. 완료 상태면 새로운 답을 받지 않습니다. 다만 이미 저장된 같은 답을 재전송한 요청이면 기존 결과를 반환합니다. 뒤의 C02~C05는 이 잠금을 가진 같은 트랜잭션에서 처리합니다.

SELECT d.student_id, d.form_id, d.status
FROM student_diagnostics d
WHERE d.student_id = :actor_id
 AND EXISTS (
   SELECT 1 FROM class_memberships m JOIN classes c ON c.id = m.class_id
   WHERE m.user_id = d.student_id AND m.role = 'student' AND m.status = 'active'
     AND c.status = 'active'
 )
FOR UPDATE;

C02. 이어할 문제와 진행률

다음 문항은 제출 행이 없는 첫 문항입니다. 정답과 채점 규칙은 학생 응답에 넣지 않습니다. selected_option_id=NULL로 명시적 ‘모르겠어요’를 제출해도 완료한 문항입니다.

SELECT q.id, q.sequence_no, q.area, q.skill, q.prompt, q.options,
       q.audio_file_id, q.image_file_id
FROM student_diagnostics d JOIN diagnostic_questions q ON q.form_id = d.form_id
LEFT JOIN diagnostic_answers a ON a.student_id = d.student_id AND a.question_id = q.id
WHERE d.student_id = :actor_id AND d.status = 'in_progress' AND a.question_id IS NULL
ORDER BY q.sequence_no LIMIT 1;

SELECT COUNT(q.id) AS total_questions, COUNT(a.question_id) AS completed_questions
FROM student_diagnostics d JOIN diagnostic_questions q ON q.form_id = d.form_id
LEFT JOIN diagnostic_answers a ON a.student_id = d.student_id AND a.question_id = q.id
WHERE d.student_id = :actor_id;

읽기 요청에서도 C01과 같은 활성 클래스 소속을 확인합니다. 진행률은 답안 행 수에서 계산하므로 따로 완료 번호를 중복 저장하지 않습니다.

C03. 답안 1개 저장

C01 잠금 후 먼저 같은 문항의 기존 답안을 확인합니다. 있으면 같은 선택값인지 비교합니다(NULL도 동일하게 비교). 같으면 기존 성공 응답을 반환, 다르면 수정 금지로 거절합니다. 없으면 C02의 다음 문항 ID와 요청 문항 ID가 같은지, 선택값이 고정 보기 안에 있는지 검사한 후 INSERT합니다. 저장된 답을 UPDATE/REPLACE하지 않습니다.

SELECT selected_option_id, submitted_at FROM diagnostic_answers
WHERE student_id = :actor_id AND question_id = :question_id;

INSERT INTO diagnostic_answers (student_id, question_id, form_id, selected_option_id)
SELECT d.student_id, q.id, d.form_id, :selected_option_id
FROM student_diagnostics d JOIN diagnostic_questions q ON q.form_id = d.form_id
WHERE d.student_id = :actor_id AND d.status = 'in_progress' AND q.id = :question_id;

1행 저장 후 C02의 완료 수를 다시 확인합니다. 미완료이면 COMMIT 후 다음 문항을 반환합니다. 마지막 문제이면 아직 COMMIT하지 않고 C04/C05까지 처리합니다.

C04. 완료 시 파트10개 채점·저장

모든 답안이 있고 total_questions > 0일 때만 실행합니다. 공개 문항집은 J00 기준으로 검증되어 있어야 합니다. 아래는 확정 루브릭의 SQL 표현입니다. 초급 판정 문항을 통과하지 못하면 초급 미달이며, 점수 경계와 난도 조건을 함께 적용합니다. 계산에 사용하는 정오/통과 횟수는 임시 집계값이고 결과 테이블에는 점수·수준만 남습니다.

INSERT INTO diagnostic_part_results (student_id, area, skill, score, level_code)
SELECT :actor_id, p.area, p.skill, p.score,
 CASE
   WHEN p.beginner_correct < 1 THEN 'below_beginner'
   WHEN p.score >= 70 AND p.intermediate_correct = 2 AND p.advanced_correct = 2 THEN 'advanced'
   WHEN p.score >= 40 AND p.intermediate_correct = 2 THEN 'intermediate'
   ELSE 'beginner'
 END
FROM (
 SELECT q.area, q.skill,
   SUM(CASE WHEN a.selected_option_id = q.correct_option_id THEN q.max_points ELSE 0 END) AS score,
   SUM(CASE WHEN q.tier = 'beginner' AND q.gate_slot IS NOT NULL
                  AND a.selected_option_id = q.correct_option_id THEN 1 ELSE 0 END) AS beginner_correct,
   SUM(CASE WHEN q.tier = 'intermediate' AND q.gate_slot IS NOT NULL
                  AND a.selected_option_id = q.correct_option_id THEN 1 ELSE 0 END) AS intermediate_correct,
   SUM(CASE WHEN q.tier = 'advanced' AND q.gate_slot IS NOT NULL
                  AND a.selected_option_id = q.correct_option_id THEN 1 ELSE 0 END) AS advanced_correct
 FROM student_diagnostics d
 JOIN diagnostic_questions q ON q.form_id = d.form_id
 JOIN diagnostic_answers a ON a.student_id = d.student_id AND a.question_id = q.id AND a.form_id = d.form_id
 WHERE d.student_id = :actor_id AND d.status = 'in_progress'
 GROUP BY q.area, q.skill
) p;

INSERT가 10행인지 확인합니다. 이 SQL을 임의의 기존 문항집에 적용하지 않습니다. gate_slot으로 지정한 초/중/고 판정 문항이 각 2개이고 각 파트 총배점이 100이어야 합니다. 규칙 버전이 바뀌면 해당 form의 rules_json에 맞는 채점기를 선택합니다.

C05. 영역종합5개 저장·완료

같은 영역의 듣기/읽기를 합산합니다. 한 파트라도 30점 미만이면 종합 초급입니다. 파트 초급 미달을 종합에 자동 전파하는 규칙은 추가하지 않았습니다.

INSERT INTO diagnostic_area_results (student_id, area, score, level_code)
SELECT student_id, area, SUM(score),
 CASE WHEN MIN(score) < 30 OR SUM(score) < 80 THEN 'beginner'
      WHEN SUM(score) < 140 THEN 'intermediate' ELSE 'advanced' END
FROM diagnostic_part_results WHERE student_id = :actor_id
GROUP BY student_id, area HAVING COUNT(*) = 2;

5행 저장을 확인한 뒤 아래 UPDATE가 1행이면 COMMIT합니다. 실패하면 마지막 답안·파트 결과·종합 결과 모두 취소합니다. 다시 접속했을 때 마지막 미저장 문항부터 이어갈 수 있습니다.

UPDATE student_diagnostics d SET d.status = 'completed', d.completed_at = UTC_TIMESTAMP(6)
WHERE d.student_id = :actor_id AND d.status = 'in_progress'
 AND (SELECT COUNT(*) FROM diagnostic_part_results p WHERE p.student_id = d.student_id) = 10
 AND (SELECT COUNT(*) FROM diagnostic_area_results a WHERE a.student_id = d.student_id) = 5;

E02. 교과 자료 쓰기의 공통 잠금

SELECT s.id, s.class_id, s.subject_code, s.created_by_user_id, s.source_text

원본은 등록 이후 본문·교과를 고정하는 정책으로 사용합니다. 고쳐야 하면 새로운 원본을 만듭니다. 전환본/문제의 출처가 바뀌지 않도록 하는 간단한 구현 기준입니다.

INSERT INTO ai_credentials (teacher_id, label, encrypted_secret, key_version, masked_suffix)

F01. 학생별 생성 요청 등록

B01→E02 통과 후 대상 학생·완료 진단·본인 키를 확인합니다. 반환된 학생의 10+5 결과와 모국어/form_id로 서버가 profile_snapshot을 만듭니다. 같은 학생의 진단을 매 작업마다 바꾸지 않습니다. :operation은 convert/generate_quiz입니다.

SELECT m.id AS student_member_id, u.id AS student_id, u.native_language_code, d.form_id
FROM class_memberships m JOIN users u ON u.id = m.user_id
JOIN student_diagnostics d ON d.student_id = u.id AND d.status = 'completed'
WHERE m.id = :student_member_id AND m.class_id = :class_id
 AND m.role = 'student' AND m.status = 'active' AND u.status = 'active'
FOR UPDATE;

SELECT id FROM ai_credentials WHERE id = :credential_id AND teacher_id = :actor_id
 AND status = 'active' AND revoked_at IS NULL FOR UPDATE;

같은 요청키가 있으면 기존 요청의 원본/학생/작업/입력 전환본이 같은지 검사하고 기존 작업을 반환합니다. 다르면 충돌로 거절합니다. 저장된 성공/실행 중 작업을 다시 Solar에 호출하지 않습니다.

SELECT id, source_material_id, target_student_member_id, input_student_material_id, operation, status
FROM ai_requests WHERE teacher_id = :actor_id AND idempotency_key = :request_key;

전환 요청은 input_student_material_id=NULL입니다. 문제 출제는 NULL이면 원본 직접 출제, 값이 있으면 같은 원본·학생의 배포된 불변 전환본인지 확인합니다. 전환본 초안을 입력으로 쓰지 않아 결과 생성 중 본문이 바뀌는 것을 막습니다.

SELECT id, converted_content FROM student_materials
WHERE id = :input_material_id AND class_id = :class_id
 AND source_material_id = :source_material_id AND student_member_id = :student_member_id
 AND status = 'published' FOR UPDATE;

입력 전환본이 없으면 위 조회는 생략합니다. 모든 검증 후 새 요청을 저장하고 COMMIT합니다.

INSERT INTO ai_requests
 (teacher_id, class_id, credential_id, source_material_id, target_student_member_id,
  input_student_material_id, operation, idempotency_key, profile_snapshot, model, prompt_version)
VALUES (:actor_id, :class_id, :credential_id, :source_material_id, :student_member_id,

F02. 작업 실행과 실패 기록

인증된 내부 작업자가 실행합니다. 실행 직전 요청 교사의 현재 권한·대상 학생·키 상태를 다시 검사합니다. 아래 UPDATE 1행 성공한 작업자만 호출합니다. DB 트랜잭션을 닫은 뒤 Solar를 호출합니다. 상태 unknown은 응답 유실 등으로 성공 여부가 불명확할 때 사용하며 무조건 재호출하지 않습니다.

UPDATE ai_requests SET status = 'running'
WHERE id = :ai_request_id AND status = 'queued';

UPDATE ai_requests SET status = :failure_status, safe_error_code = :safe_error_code,
 finished_at = UTC_TIMESTAMP(6)
WHERE id = :ai_request_id AND status = 'running';

:failure_status는 failed/unknown입니다. 에러 메시지에 원문 키를 저장하지 않습니다. 성공은 결과 저장과 함께 G00 또는 H00 트랜잭션에서 확정합니다. 완료 저장 시에도 권한이 취소되었으면 배포 가능한 결과를 만들지 않습니다.

G. 학생별 전환본 생성·검토·배포

G00. 생성 결과 저장

내부 작업자가 요청자의 A01에 해당하는 계정 상태 및 B01/E02 권한, 대상 학생 상태를 다시 확인합니다. 외부 요청자가 성공 상태나 생성자 ID를 지정하지 않습니다. 요청 행을 FOR UPDATE로 잠가 operation=convert/status=running임을 확인하고 그 행의 클래스·원본·학생·교사를 사용합니다. 이미 succeeded면 기존 결과를 반환합니다.

SELECT * FROM ai_requests WHERE id = :ai_request_id FOR UPDATE;

SELECT COALESCE(MAX(revision), 0) + 1 AS next_revision
FROM student_materials
WHERE source_material_id = :source_material_id AND student_member_id = :student_member_id;

E02의 원본 잠금 하에 순번을 얻고 다음 INSERT를 실행합니다. AI 결과 JSON의 구조와 학습 내용은 서버 검증 후 저장하며, 학생용 공개는 교사 검토 이후입니다.

INSERT INTO student_materials
 (class_id, source_material_id, student_member_id, revision, ai_request_id,
  created_by_user_id, converted_content, diagnosis_snapshot)
SELECT class_id, source_material_id, target_student_member_id, :next_revision, id,
       teacher_id, :converted_content_json, profile_snapshot
FROM ai_requests WHERE id = :ai_request_id AND operation = 'convert' AND status = 'running';

UPDATE ai_requests SET status = 'succeeded', input_tokens = :input_tokens,
 output_tokens = :output_tokens, finished_at = UTC_TIMESTAMP(6)
WHERE id = :ai_request_id AND status = 'running';

결과 INSERT와 요청 UPDATE 각각 1행일 때 COMMIT합니다. 자동 생성 결과는 draft이며 학생에게 보이지 않습니다.

G01. 초안 수정·검토·배포

B01→E02→아래 행 잠금 순서입니다. 객체의 class/source 일치를 검증하고 작성자 또는 클래스 소유자인지 확인합니다. 수정 시 화면에서 받은 updated_at과 실제 값을 비교해 동시 수정 충돌을 거절합니다. 배포 이력이 있는 행은 수정하지 않습니다.

SELECT id, class_id, source_material_id, student_member_id, created_by_user_id,
       status, updated_at, published_at
FROM student_materials WHERE id = :student_material_id FOR UPDATE;

초안 수정은 검토 완료를 해제합니다. 아래 세 UPDATE는 각각 수정 / 검토 / 배포 버튼의 별도 동작이며 연속 자동 실행하지 않습니다.

UPDATE student_materials SET converted_content = :converted_content_json,
 status = 'draft', reviewed_by_user_id = NULL, reviewed_at = NULL
WHERE id = :student_material_id AND status IN ('draft','reviewed')
 AND published_at IS NULL AND updated_at = :expected_updated_at;

UPDATE student_materials SET status = 'reviewed', reviewed_by_user_id = :actor_id,
 reviewed_at = UTC_TIMESTAMP(6)
WHERE id = :student_material_id AND status = 'draft' AND published_at IS NULL;

배포 직전 대상 학생이 여전히 같은 클래스의 활성 학생인지 다시 확인합니다. 배포 요청도 화면에서 검토한 버전(updated_at)과 일치해야 합니다.

UPDATE student_materials SET status = 'published', published_by_user_id = :actor_id,
 published_at = UTC_TIMESTAMP(6)
WHERE id = :student_material_id AND status = 'reviewed' AND published_at IS NULL
 AND updated_at = :expected_updated_at;

재배포/변경은 새 revision을 생성합니다. 배포 취소는 삭제 대신 withdrawn을 사용합니다. 같은 전환본을 사용하는 배포 문제도 함께 withdrawn 처리하는 것을 기본 정책으로 합니다.

UPDATE quizzes SET status = 'withdrawn'
WHERE student_material_id = :student_material_id AND status = 'published';

UPDATE student_materials SET status = 'withdrawn'
WHERE id = :student_material_id AND status = 'published';

두 철회 문장은 B01/E02 및 해당 전환본의 편집 권한을 확인한 동일 트랜잭션에서 실행합니다. 다른 교사가 만든 연결 문제도 입력 전환본 철회에 따라 비공개로 전환하되 본문·풀이 이력은 삭제하지 않습니다.

H. 자료 기반 문제 생성·검토·배포

H00. AI 문제 묶음과 문항 저장

F01/F02에서 generate_quiz 작업으로 생성합니다. 성공 저장은 G00과 같은 잠금·권한·중복 확인 흐름입니다. 원본 또는 배포된 입력 전환본의 정확한 본문을 SHA-256으로 계산하여 source_hash에 저장합니다. 문항 유형은 true_false 또는 multiple_choice_4입니다. 보기 ID 중복·정답 포함·출처 문장 존재·문항 수>0을 서버에서 검증합니다.

SELECT COALESCE(MAX(generation_no), 0) + 1 AS next_generation
FROM quizzes WHERE source_material_id = :source_material_id AND student_member_id = :student_member_id;

INSERT INTO quizzes
 (class_id, source_material_id, student_member_id, student_material_id, ai_request_id,
  created_by_user_id, title, generation_no, question_type, source_hash)
SELECT class_id, source_material_id, target_student_member_id, input_student_material_id, id,
       teacher_id, :title, :next_generation, :question_type, :source_hash_bytes
FROM ai_requests WHERE id = :ai_request_id AND operation = 'generate_quiz' AND status = 'running';

새 quiz ID를 얻고 아래 INSERT를 문항 수만큼 executemany로 반복합니다. 문항들이 모두 저장된 뒤 G00의 요청 성공 UPDATE를 실행하고 COMMIT합니다. 일부 문항만 저장한 상태로 성공 처리하지 않습니다.

SELECT id, class_id, source_material_id, student_member_id, student_material_id,
       created_by_user_id, status, published_at, updated_at

초안 문항 수정 시 아래 두 UPDATE를 하나의 트랜잭션에서 실행합니다. 첫 UPDATE 1행을 확인한 뒤 부모 검토 상태를 해제합니다. 부모 published_at이 있으면 수정하지 않습니다. 수정해도 새 문항 내용은 보기·정답·출처 검증을 통과해야 합니다.

UPDATE quiz_questions qq JOIN quizzes q ON q.id = qq.quiz_id
SET qq.prompt = :prompt, qq.choices = :choices_json,

UPDATE quizzes SET status = 'draft', reviewed_by_user_id = NULL, reviewed_at = NULL,
 updated_at = UTC_TIMESTAMP(6)
WHERE id = :quiz_id AND published_at IS NULL AND status IN ('draft','reviewed');

검토 버튼은 문항 존재·모든 문항 유효성을 확인한 뒤 별도로 실행합니다.

WHERE id = :quiz_id AND status = 'draft' AND published_at IS NULL
 AND EXISTS (SELECT 1 FROM quiz_questions qq WHERE qq.quiz_id = :quiz_id);

배포 버튼은 대상 학생 활성 여부와 입력 전환본의 배포 상태까지 확인합니다. 배포 뒤 문항·정답·해설은 고정하고 수정은 새 generation_no로 생성합니다.

WHERE q.id = :quiz_id AND q.status = 'reviewed' AND q.published_at IS NULL

I01. 문제 접근 확인·풀이 시작 잠금

읽기에서는 FOR UPDATE 없이, 제출에서는 트랜잭션 내에서 잠급니다. 0행이면 중단합니다. 문제 배정과 클래스·배포 상태·진단 완료를 매번 확인합니다.

SELECT q.id, q.student_material_id, q.source_material_id

SELECT quiz_id, status, first_score, max_score FROM quiz_submissions
WHERE quiz_id = :quiz_id FOR UPDATE;

INSERT INTO quiz_submissions (quiz_id, max_score)
SELECT :quiz_id, SUM(max_points) FROM quiz_questions

I02. 최초 제출/오답 재풀이 저장

I01 및 풀이 상태 잠금 후 아래 순서로 처리합니다. request_key는 한 번의 논리적 제출마다 발급하고 네트워크 재전송 시 같은 값을 유지합니다.

SELECT question_id, selected_option_id, is_correct, points, attempt_no
FROM quiz_answer_attempts WHERE quiz_id = :quiz_id AND request_key = :request_key;

기록이 있으면 같은 question_id/선택지인지 확인합니다. 같으면 기존 결과를 반환하고 새 행을 만들지 않습니다. 다른 내용이면 요청키 충돌입니다. 새 요청일 때만 다음으로 진행합니다.

SELECT id, choices, correct_option_id, max_points
FROM quiz_questions WHERE id = :question_id AND quiz_id = :quiz_id;

SELECT attempt_no, is_correct FROM quiz_answer_attempts
WHERE quiz_id = :quiz_id AND question_id = :question_id
ORDER BY attempt_no DESC LIMIT 1;

이력이 없으면 attempt_no=1, 마지막 답이 오답이면 마지막 번호+1입니다. 마지막 답이 정답이면 새 재풀이 제출을 거절합니다. 선택지가 보기에 속하는지 서버가 검증합니다. 다음 INSERT는 DB 정답으로 정오·점수를 계산하므로 학생이 점수를 전달하지 않습니다.

INSERT INTO quiz_answer_attempts
 (quiz_id, question_id, attempt_no, selected_option_id, is_correct, points, request_key)
SELECT quiz_id, id, :next_attempt_no, :selected_option_id,
       (correct_option_id = :selected_option_id),
       CASE WHEN correct_option_id = :selected_option_id THEN max_points ELSE 0 END,
       :request_key
FROM quiz_questions WHERE id = :question_id AND quiz_id = :quiz_id;

최초 답안 수가 문제 수와 같아지면 최초 성적을 확정합니다. 아래 UPDATE는 completed에는 적용되지 않아 재풀이로 첫 점수를 덮어쓰지 않습니다. 새로운 제출과 최초 성적 갱신을 함께 COMMIT합니다. 상태 미생성/미완료를 0점으로 표시하지 않습니다.

UPDATE quiz_submissions sub
SET sub.first_score = (
 SELECT SUM(a.points) FROM quiz_answer_attempts a WHERE a.quiz_id = sub.quiz_id AND a.attempt_no = 1
), sub.first_submitted_at = UTC_TIMESTAMP(6), sub.status = 'completed'
WHERE sub.quiz_id = :quiz_id AND sub.status = 'in_progress'
 AND (SELECT COUNT(*) FROM quiz_questions qq WHERE qq.quiz_id = sub.quiz_id) > 0
 AND (SELECT COUNT(*) FROM quiz_answer_attempts a WHERE a.quiz_id = sub.quiz_id AND a.attempt_no = 1)
     = (SELECT COUNT(*) FROM quiz_questions qq WHERE qq.quiz_id = sub.quiz_id);

I03. 해설과 재풀이 횟수

학생이 누를 때마다 I01 읽기 권한을 확인합니다. 해설은 해당 학생의 문항에 첫 제출이 있을 때만 보여 줍니다. 버튼 클릭 기록 테이블은 필요하지 않습니다.

SELECT qq.id, qq.correct_option_id, qq.explanation
FROM quiz_questions qq
WHERE qq.id = :question_id AND qq.quiz_id = :quiz_id
 AND EXISTS (SELECT 1 FROM quiz_answer_attempts a
             WHERE a.quiz_id = qq.quiz_id AND a.question_id = qq.id AND a.attempt_no = 1);

학생은 I01, 교사는 B01/E02 및 해당 quiz의 원본 일치를 확인한 뒤 아래 조회를 사용합니다. 미제출은 최신 정오 NULL, 재풀이0입니다. 횟수는 버튼 클릭이 아닌 저장된 답안 수−1입니다.

SELECT qq.id, qq.position,
       CASE WHEN COUNT(a.attempt_no) = 0 THEN 0 ELSE COUNT(a.attempt_no) - 1 END AS retry_count,
       (SELECT last_a.is_correct FROM quiz_answer_attempts last_a
        WHERE last_a.quiz_id = qq.quiz_id AND last_a.question_id = qq.id
        ORDER BY last_a.attempt_no DESC LIMIT 1) AS latest_is_correct
FROM quiz_questions qq LEFT JOIN quiz_answer_attempts a
 ON a.quiz_id = qq.quiz_id AND a.question_id = qq.id
WHERE qq.quiz_id = :quiz_id
GROUP BY qq.id, qq.quiz_id, qq.position ORDER BY qq.position;

I04. 교사의 최근 배포와 풀이 내역

A01의 검증된 교사에게 제공하며 교과 조건을 SQL에 포함합니다. 최근 배포는 published_at, 최근 실제 활동은 last_answered_at 기준이므로 서로 다른 값입니다. 최신 활동순 화면은 ORDER BY를 last_answered_at DESC로 바꿉니다.

SELECT q.id, q.title, q.published_at, u.display_name,
       sub.status AS progress_status, sub.first_score, sub.max_score,
       (SELECT MAX(a.answered_at) FROM quiz_answer_attempts a WHERE a.quiz_id = q.id) AS last_answered_at
FROM quizzes q
JOIN source_materials s ON s.id = q.source_material_id AND s.archived_at IS NULL
JOIN classes c ON c.id = q.class_id AND c.status = 'active'
JOIN class_memberships t ON t.class_id = q.class_id AND t.user_id = :actor_id
 AND t.role = 'teacher' AND t.status = 'active' AND t.teacher_subject_code = s.subject_code
JOIN class_memberships m ON m.id = q.student_member_id
JOIN users u ON u.id = m.user_id
LEFT JOIN quiz_submissions sub ON sub.quiz_id = q.id
WHERE q.class_id = :class_id AND q.status = 'published'
ORDER BY q.published_at DESC, q.id DESC LIMIT 100;

교사 전환본 목록은 E01의 원본 조건에 student_materials를 JOIN하고, 문제 목록은 quizzes를 JOIN합니다. 초안/검토/배포 상태를 모두 볼 수 있고, 상세는 같은 조건에 ID를 추가합니다. 학생 목록과 교사 목록의 응답을 공용으로 재사용해 정답·초안을 노출하지 않습니다.

ORDER BY q.created_at DESC, q.id DESC LIMIT 100;

K01. 학생 전환본 상세 / 문제 상세

A01 학생 인증·진단 완료 확인 뒤 첫 쿼리를 사용합니다. 두 번째 쿼리는 I01 읽기 권한 통과 뒤에만 사용합니다. 조회 결과에 정답·해설은 넣지 않았습니다.

SELECT sm.id, s.title, s.subject_code, sm.converted_content, sm.converted_file_id
FROM student_materials sm JOIN source_materials s ON s.id = sm.source_material_id
JOIN classes c ON c.id = sm.class_id AND c.status = 'active'
JOIN class_memberships m ON m.id = sm.student_member_id AND m.class_id = sm.class_id
WHERE sm.id = :student_material_id AND sm.class_id = :class_id
 AND m.user_id = :actor_id AND m.role = 'student' AND m.status = 'active'
 AND sm.status = 'published' AND s.archived_at IS NULL;

SELECT qq.id, qq.position, qq.question_type, qq.prompt, qq.choices, qq.max_points,
 CASE WHEN q.student_material_id IS NULL THEN s.source_text ELSE NULL END AS original_passage,
 sm.converted_content AS converted_passage
FROM quizzes q JOIN quiz_questions qq ON qq.quiz_id = q.id
JOIN source_materials s ON s.id = q.source_material_id
LEFT JOIN student_materials sm ON sm.id = q.student_material_id
WHERE q.id = :quiz_id ORDER BY qq.position;

K02. 교사용 문항 검토 상세

B01/E02 뒤 해당 quiz가 검증한 클래스·원본에 속하는지 확인합니다. 다음 응답은 교사용이며 학생 API에 재사용하지 않습니다.

SELECT qq.id, qq.position, qq.question_type, qq.prompt, qq.choices,
       qq.correct_option_id, qq.explanation, qq.source_sentence_ids, qq.max_points
FROM quiz_questions qq JOIN quizzes q ON q.id = qq.quiz_id
WHERE q.id = :quiz_id AND q.class_id = :class_id AND q.source_material_id = :source_material_id
ORDER BY qq.position;

K03. 파일 메타데이터 조회

다음 쿼리의 :authorized_file_id는 요청의 file_id를 그대로 대입하지 않습니다. 교사는 B01/E01 또는 허용된 전환본 상세에서, 학생은 K01의 본인 배포 전환본에서 얻은 파일 ID여야 합니다. 진단 파일은 C02로 허용된 문항에서 얻습니다. 원본 직접 출제 파일을 제공하는 경우에도 I01로 해당 지문의 접근 권한을 먼저 검사합니다.

SELECT id, object_key, original_name, mime_type, size_bytes
FROM files WHERE id = :authorized_file_id AND scan_status = 'clean' AND deleted_at IS NULL;

object_key는 서버 내부 저장소 접근용입니다. 학생에게 공개 버킷 경로나 장기 유효 주소로 그대로 넘기지 않습니다.

파일 접근과 구현 범위

파일 ID만으로 files를 조회해 공개하면 안 됩니다. 교사는 E01의 허용 원본 또는 연결 전환본을, 학생은 I00의 본인 배포 전환본 또는 I01의 허용 지문을 통해 파일 권한을 확인합니다. 원본 직접 출제 시 원본 본문/필요한 지문을 제공할 수 있지만 전환본 출제에서 원본 PDF 전체를 자동 공개하지 않습니다. 진단 음원/이미지는 현재 배정된 진단 문항을 통해 제공합니다. 검사된 파일(clean), 미삭제 파일인지 확인한 뒤 서버가 파일을 전송하거나 짧은 만료 URL을 발급합니다.

DB가 하지 않는 일: 비밀번호 검증·API 키 암호화·교사 자격 확인·PDF 추출·Solar 생성·HTTP 세션 처리·조건 분기·화면 이동·파일 제공. 이 기능들은 위 SQL 호출을 감싸는 서버 코드에서 구현합니다. 진단은 확정 루브릭과 정답으로 채점하고 Solar에 수준 판정을 맡기지 않습니다.

이 초안의 SQL 문법 검증 결과와 범위는 별도 검증 메모를 참고합니다. 앱 기능의 구현 완료나 실제 사용자 DB 반영을 뜻하지 않습니다.
