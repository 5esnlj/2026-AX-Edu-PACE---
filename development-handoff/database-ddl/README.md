# 가나다계단 MariaDB 실행 안내

이 파일 묶음은 화면에서 확인된 **MariaDB 11.8.6**, 데이터베이스 이름 **ganada**에 맞춘 신규 생성용입니다. HeidiSQL은 접속 프로그램이며, 실제 DB 서버 종류는 화면 아래에 표시됩니다.

## 이번 오류의 원인

화면 아래 실행 기록이 `ai_request_id BIGINT UNSIGNED NULL, created_by_user_id ...`로 시작합니다. 이 부분은 `CREATE TABLE quizzes (...)` 안에 있어야 하는 컬럼 정의입니다. SQL 전체에서 일부만 복사했거나 일부 구간을 선택 실행한 것으로 보이며, 실제 실행된 SQL에 테이블 생성 시작 부분이 빠져 있으므로 1064 구문 오류가 납니다. 컬럼 이름 자체의 문제가 아닙니다.

기존 전달본은 MySQL 8.4용이었습니다. 이번 파일은 MariaDB용으로 별도 제공하며 DB 이름을 ganada, 문자 정렬 규칙을 utf8mb4_unicode_ci로 맞췄습니다. 이미 빈 ganada DB가 존재해도 테이블마다 같은 문자셋/정렬 규칙을 적용합니다. 기존 20개 테이블 구조와 교과 접근 정책은 유지했습니다.

## 실행 순서

1. 오류 창을 닫습니다. 먼저 별도 쿼리 탭에서 다음만 실행합니다.

```sql
SELECT VERSION(), DATABASE();
SHOW TABLES FROM ganada;
```

2. `SHOW TABLES` 결과가 비어 있을 때 아래 생성을 진행합니다. 테이블이 이미 나오면 생성문을 반복하거나 테이블을 삭제하지 말고 목록과 오류를 확인해야 합니다. 왼쪽의 `0 B` 표시만으로 빈 DB라고 단정하지 않습니다.
3. **01_create_tables.sql을 파일 전체로** 새 쿼리 탭에 불러옵니다. HeidiSQL의 파일 → SQL 파일 불러오기를 사용하고 UTF-8로 엽니다. 기존에 잘린 SQL 아래에 덧붙이지 않습니다.
4. 파일 맨 위에 `SET NAMES`, `CREATE DATABASE IF NOT EXISTS ganada`, `USE ganada`가 있고, 그 뒤 첫 테이블이 `CREATE TABLE users (`로 시작하는지 확인합니다.
5. 편집 영역에서 **Ctrl+A로 파일 전체를 선택**하고 쿼리 메뉴의 실행을 누릅니다(기본 F9). 부분 구간이나 현재 문장만 실행하는 메뉴가 아니라 전체 선택 구간을 실행합니다.
6. 마지막 결과 `created_table_count`가 **20**이면 정상입니다. 왼쪽 ganada를 새로 고침하고 펼치면 테이블이 보입니다.

기존 데이터를 삭제하는 DROP 문은 없습니다. MySQL/MariaDB의 DDL은 중간 실패 시 앞서 만든 테이블까지 자동 취소되지 않습니다. `Table already exists`가 나오면 반복 실행하지 말고 생성된 테이블 상태를 확인합니다. 기존 테이블 업그레이드용 마이그레이션은 아닙니다.

## 포함 파일

- `01_create_tables.sql`: 20개 테이블 생성. 처음부터 끝까지 한 번 실행합니다.
- `02_authorized_queries.sql`: 서버 구현에 사용할 조회 예시. 테이블 생성에는 필요하지 않습니다. 사용자 ID 매개변수는 로그인 세션에서 서버가 정해야 합니다.
- `검증결과.md`: 별도의 임시 MariaDB에 가상 데이터를 넣어 검증한 결과. 사용자 PC의 DB를 직접 수정하거나 검증한 결과는 아닙니다.

교사의 담당 교과는 클래스별 1개이며, 해당 클래스의 활성 교사이고 자료의 교과가 일치할 때만 자료·전환본·문제·파일에 접근하도록 조회합니다. 클래스 소유자도 같은 제한을 받습니다. **DDL만 실행하면 웹앱 권한이 자동 적용되는 것은 아니므로 백엔드에 조회 조건도 적용해야 합니다.**

진단 결과는 5영역×듣기/읽기 10행과 영역별 종합 5행이며 식별 키·점수·수준만 저장합니다. 답안 기록으로 진단 이어하기를 처리합니다. 교사 생성·검토·배포, 학생별 자료/문제, 오답 재풀이 기록도 기존 구조를 유지했습니다. 실제 진단 문항·루브릭 등록 및 서버 채점은 별도 구현 사항입니다.
