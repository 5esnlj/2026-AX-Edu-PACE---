# 이후 백엔드 개발에서 이어 사용할 기준

작성일 2026-11-21. 프로젝트 이름 가나다계단. 이 문서를 API/OpenAPI와 함께 다음 개발자 또는 AI에게 전달합니다. 대화 밖의 영구 기억을 전제로 하지 않고 기준 파일을 묶음에 보존했습니다.

1. `baseline/schema_mariadb_11_8.sql`: 사용자와 합의한 기존20개 테이블 DDL. 이 API 작업에서 실제 DB나 이 스냅샷을 변경하지 않았습니다.
2. `baseline/DML_설계.md`: 직전 작성한 기능별 DML88개와 트랜잭션·권한 전제. 실제 백엔드의 repository/service 구현 기준입니다.
3. `handoff/HANDOFF.md`: 첨부된 19개 화면과 Figma 프레임 주소. 화면 속 숫자·이름은 예시입니다.
4. `decisions.md`: 화면 설명과 확정 요구가 다른 부분의 우선순위, 새 제안과 미구현 범위.
5. `openapi.json`, `API_SPEC.md`: 이번 API 초안. 실제 백엔드는 계약을 유지하면서 mock 내부를 DML 호출로 교체합니다.

## 보존할 결정

- 교사 개설→교사/학생 역할별 초대→클래스 소속. 역할은 인증된 계정에서 결정.
- 교사 자신의 클래스 담당 교과만 자료·문제·연결 파일·풀이 내역 접근. 소유자 예외 없음. 학생은 본인에게 배포된 것만.
- 5영역(국어/수학/사회/과학/생활한국어) × 듣기/읽기100점 = 파트10개. 같은영역 종합200점 = 결과5개. 초급미달/초급/중급/고급. 전체영역을 합친 임의 단일등급 없음.
- 학생 계정당 최초진단 한번, 제출한 고정답 문항만 저장, 다음 미제출문항 재개. 최종답안·결과15개·완료표시는 한 트랜잭션. 판단근거 저장 없음.
- 교사만 AI생성. 학생별 자료·문제. 원본직접출제 또는 전환본출제. T/F 또는4지선다. 교사검토후배포. 배포본문/정답 불변.
- 최초점수와 재풀이후현재성적을 분리. 재풀이횟수=성공저장한응답수−1. 같은요청 재전송으로 횟수증가금지.
- 교사개인 Solar키. 다른교사의키를 공유하거나 브라우저에반환하지 않음.
- 배움길·메시지·오역탐지·아는/모르는단어기록·말하기/쓰기·6수준·진단회차 제외.

## 새 제안 — 아직 실제 DB에 적용하지 않음

교사 초대 링크에서 교과를 안전하게 확정하려면 `class_invitations.teacher_subject_code` nullable 컬럼을 추가하는 최소변경을 권합니다. 소유자가 초대를 발급할 때 정하고, 수락자가 임의로 교과를 바꿀 수 없게 합니다. 현재 DDL을 그대로 사용할 경우 소유자가 별도 승인한 담당 교과로 가입을 처리해야 합니다. mock의 초대교과 보관은 이 제안의 시뮬레이션이며 기존 DB에 이미 컬럼이 있는 것으로 가정하면 안 됩니다.

## mock → 실제 서비스 교체 지점

mock의 메모리딕셔너리→MariaDB repository, mock비밀번호검사→Argon2id 검증, 개발용세션→운영세션/쿠키 정책, 합성PDF본문→비공개저장소+파일검사+PDF추출, 즉시완료mock작업→작업큐+Solar 호출, 합성진단70문항→검증된공식문항집으로 교체합니다. API키 암호화·초대 동시사용·행잠금·트랜잭션·동시수정검사는 실제DB에서 별도로 통합검증해야 합니다.

첨부 CLAUDE.md의 명령은 참고자료로 읽었으며 프로젝트 규칙 파일로 자동 설치하거나 원본 앱에 복사하지 않았습니다. 1.1 수정본은 API 설계·mock과 첨부 FE의 별도 연결본을 포함합니다. 실제 프론트/백엔드 저장소의 배포 변경은 없습니다. 추가 변경과 개발 순서는 상위 폴더 API_CHANGES.md 및 DEVELOPMENT_PLAN.md를 따릅니다.
