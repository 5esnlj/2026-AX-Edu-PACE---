# API mock 검증 계획

이 테스트는 FastAPI mock을 실제 HTTP 요청/응답 형태로 호출합니다. SQLite/MariaDB나 Solar를 연결한 통합 테스트가 아닙니다. 테스트마다 메모리 상태를 초기화하여 결과가 다른 테스트에 의존하지 않도록 합니다.

실행: `python -m unittest -v test_api`

| 검증 묶음 | 확인 사항 | 관련 화면 |
|---|---|---|
| 인증 | 잘못된 비밀번호/역할, 인증 없는 접근, 세션 확인, CSRF, 로그아웃 | 공통01 |
| 클래스·초대 | 소속 목록, 교사 개설, 학생 개설 거부, 역할·사용횟수·교과가 지정된 초대 | 교사01 / 학생02 |
| 교사 자료 범위 | 자기 교과만 목록/상세/다운로드, 클래스 소유자의 다른 교과 우회 차단, 타 클래스 차단 | 교사02~09 |
| 학생 배정 범위 | 본인에게 배포된 항목만, 다른 학생·초안·미완료 진단 접근 차단 | 학생03~08 |
| 진단 | 70개 가상 문항, 이어하기, 중복/다른 답 거절, 순서 검사, 결과10파트+5종합, 점수·과락 경계 | 학생01·09 / 교사09 |
| 생성 | 학생별 작업/결과, 재전송 키, 다른 입력의 키 충돌, T/F·4지선다, 실제 Solar 호출 없음 | 교사04·07 |
| 검토·배포 | 초안→검토→배포, 동시 수정 충돌, 수정 시 검토 해제, 배포본 불변 | 교사05·08 |
| 문제 풀이 | 정답 사전 노출 금지, 첫 제출·재풀이·해설, 최초 성적 보존, 유효 제출 수 기반 횟수 | 학생06~08 |
| 요약 | 문제 묶음과 문항 수 구분, 미제출과 오답 구분, 영역 선택에 따른 수준 표시 | 교사02 / 학생03·09 |
| OpenAPI | 문서 생성, 주요 메서드 존재, 가능한 경우 응답 스키마와 실제 응답 비교 | 모든 화면 |

확정되지 않은 디자인 요소와 DB 변경 제안은 `decisions.md`를 따릅니다. 생성 결과와 진단 문항은 테스트용 예시이며 실제 수업자료/공식 진단 문항으로 사용하면 안 됩니다.

## 실행 결과

2026-11-21, Python 3.12의 `unittest`와 FastAPI TestClient로 **25개 테스트를 통과**했습니다. 정상 응답은 제공된 OpenAPI의 해당 응답 스키마로 검증합니다. 진단 전체 70개 답안 제출을 실제 HTTP 흐름으로 수행해 40점/70점 경계와 과락, 10개 파트/5개 종합 결과를 확인했습니다.

초기 테스트가 발견한 문제는 문항 목록에서 `nextCursor:null`이 누락되던 응답 문제였습니다. 서버 수정 후 목록과 학생 정답 비노출 검증이 모두 통과했습니다. API 키를 큐 등록 시점에 고정하고 해제된 키를 다른 키로 바꿔 실행하지 않는 회귀검사, 보관 원본의 파일/활동 접근 차단, 미확인 교사 로그인 차단도 포함했습니다. 가중 점수 8/10과 정답 문항 수 2/3이 별개임을 확인했습니다.

이 실행 환경에서는 샌드박스 안의 TestClient 스레드 통신이 멈춰, 외부 접속 없이 로컬 테스트 프로세스에 한해 실행 권한을 조정했습니다. 사용자 PC에서는 일반적으로 위 실행 명령을 사용하면 됩니다.
