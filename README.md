# 이음 · 함께 자라는 교실

**다문화 혼합 학급의 학습 한국어를 지원하는 PACE 해커톤 개발 프레임워크**입니다.
첨부된 `[해커톤 개발] 설계안.pdf`의 교사·학생 흐름을 React 화면, FastAPI API, SQLite 저장소로 연결했습니다.

> **합성 학생 데이터 + 데모 로그인**으로 실행합니다. 자료·교과어·문항 생성은 규칙 기반 데모 또는 **Solar API**를 선택할 수 있습니다. OCR·운영 인증은 후속 구현이며 진단·번역 결과는 전문 검증되지 않았습니다.

**Windows / VS Code에서 Solar 연결:** [설치·키 입력·실행·문제 해결 안내](docs/solar-setup.md)를 따라 진행하세요.

**교사용 L1 에이전트:** [첨부 모듈 통합 내용·프로필 등록·검토·배포 안내](docs/teacher-l1-integration.md). 새 자료는 기본으로 프로필 기반 자동 재구성을 사용합니다.

## 빠른 시작

필수: **Node.js 22.12 이상(이 환경: 24), npm, Python 3.12 이상**. Linux/macOS 기준입니다.

```bash
cd /workspace/2026-AX-Edu-PACE---
bash scripts/setup.sh
npm run dev
```

설치 스크립트는 `.venv`를 만들고 Python 의존성을 설치하며, `npm ci`와 프로덕션 빌드를 실행합니다.
개발 명령은 `.venv`의 Python을 우선 사용하고 API(8000)·Vite(5173)를 함께 실행합니다. 프론트엔드와 Python 코드는 자동 갱신됩니다. 종료는 `Ctrl+C`입니다.

첫 화면에서 **선생님 / 학생** 역할을 선택해 입장합니다. 실제 가입 없이 사용할 수 있으며, 학생 모드에서는 예시 학생을 선택할 수 있습니다. 왼쪽 아래 로그아웃 버튼으로 역할을 바꿉니다.

별도 실행이 필요하면:

```bash
npm run dev:api
npm run dev:web
```

## 권장 데모 순서

1. **교사 → 맞춤 자료 만들기 → 예제 불러오기**: 사회 ‘민주주의와 시민 참여’ 원문을 사용합니다.
2. 대상 학생과 교과를 선택하고 L1 자동 재구성을 사용합니다. 상세 진단은 학생 관리의 **L1 프로필**에서 등록할 수 있습니다.
3. 학생별 탭에서 원문·문장별 근거·어휘 위계·번역·시각 자료를 검토합니다. **검토 내용 저장**으로 수정을 보관할 수 있습니다.
4. 각 학생의 검토 확인란을 체크하고 **이 학생의 검토 완료**를 누릅니다. 전원 검토 후 배포합니다.
5. **이해 확인 문항 만들기**로 문항을 배포합니다. 데모 문항 생성은 내장된 예제 원문만 지원합니다.
6. 로그아웃 후 **학생(누리)**으로 입장해 수업 자료를 읽습니다. 단어 상태·메모를 저장하고 이해 확인을 풉니다.
7. 다시 교사로 입장해 **학습 리포트**에서 해당 응답과 지원 참고 신호를 확인합니다.

## 명령과 검증

```bash
npm run build      # TypeScript 검사 + Vite 프로덕션 빌드
npm test           # 독립 임시 DB에서 API 통합 + 모의 Solar 테스트
npm run test:e2e   # 별도 서버·임시 DB에서 L1 및 기존 브라우저 흐름 검증
npm run format    # 프론트엔드·문서 포맷
```

브라우저 테스트는 기본 `/usr/bin/chromium`을 사용합니다. 다른 환경에서는 `CHROMIUM_PATH`에 실행 파일 경로를 지정하세요. 테스트 서버는 5174/8001 포트를 사용하며 개발 DB에 쓰지 않습니다. 실패 시 `test-results/`에 화면과 trace를 남깁니다.

API 문서는 API 서버의 `/docs`, 상태 확인은 `/api/health`입니다. 빌드 후 `npm run dev:api`만 실행하면 FastAPI가 `dist/`와 API를 같은 출처에서 제공합니다. **이 방식도 운영 배포 준비 완료를 의미하지 않습니다.**

## 데이터와 환경 설정

- DB는 기본 `.data/ieum.db`에 저장되며 재시작해도 유지됩니다.
- 합성 학생 6명, 배포된 예제 자료 1개, 예제 문항 1세트, 출처가 표시된 예시 풀이 3개가 최초 1회 생성됩니다.
- PDF 원본 파일은 디스크에 보관하지 않고 텍스트만 추출합니다. 생성 자료에는 원문 텍스트를 저장합니다.
- DB·가상환경·빌드 산출물은 Git에 포함하지 않습니다. 초기화하려면 서버 종료 후 DB를 **백업·이동**하세요. 다음 시작 시 예시 교실이 생성됩니다.
- `.env.example`을 `.env`로 복사하면 Python 서버가 자동으로 읽습니다. 셸 환경 변수가 우선합니다. 포트 설정은 Node 실행기가 읽으므로 셸에서 설정합니다.

| 변수                  | 기본값                   | 용도                                                                |
| --------------------- | ------------------------ | ------------------------------------------------------------------- |
| `IEUM_AGENT_PROVIDER` | `demo`                   | `solar`로 설정하면 새 자료·문항에 Solar 사용                        |
| `UPSTAGE_API_KEY`     | 없음                     | 서버 전용 Upstage API 키                                            |
| `SOLAR_MODEL`         | `solar-pro2`             | 계정에서 사용할 수 있는 Solar 모델 ID                               |
| `IEUM_DB_PATH`        | 저장소의 `.data/ieum.db` | SQLite 파일 위치                                                    |
| `IEUM_DEMO_ENABLED`   | `true`                   | `false`이면 새 데모 입장·공개 예시 목록 차단. 실제 인증은 별도 필요 |
| `IEUM_SECURE_COOKIES` | `false`                  | HTTPS 환경에서는 `true`                                             |
| `IEUM_API_PORT`       | `8000`                   | 개발 API 포트                                                       |
| `IEUM_WEB_PORT`       | `5173`                   | 통합 개발 실행기의 Vite 포트                                        |
| `CHROMIUM_PATH`       | `/usr/bin/chromium`      | 브라우저 테스트 실행 파일                                           |

데모 모드는 외부 키가 필요하지 않습니다. Solar 키는 서버의 `.env` 또는 서버 환경 변수로만 제공하고 프론트엔드 코드나 `VITE_` 변수에 넣지 마세요. `/api/health`의 `configured`는 키 입력 여부이며 실제 인증 성공을 뜻하지 않습니다.
